# Задача 3. Движок кандидатов

Движок раз в сутки собирает кандидатов из нескольких источников по семенам пользователя и пополняет его пул.

## Семена по пользователю
Лайки, топ по прослушиваниям и свежие promote. Вес семени затухает с полураспадом около 90 дней.

## Адаптеры источников
Общий интерфейс: на выходе артист, название, альбом, схожесть 0..1, источник и внешние id.
- **Last.fm:** `track.getSimilar`; цепочка `artist.getSimilar` → `artist.getTopTracks` (3–5 треков от похожих
  артистов, которых нет в библиотеке); теги семян → `tag.getTopTracks`.
- **Deezer** (без ключа; если из России не отвечает — через VPN): поиск семени для получения id, затем
  `/artist/{id}/related` и `/artist/{id}/radio`.
- **ListenBrainz:** LB Radio по артистам и тегам семян; плейлисты Weekly Exploration и Weekly Jams, когда они начнут
  появляться; включить скробблинг в LB для обоих пользователей.
- **yandex_archive:** рёбра similar, wave и artist_similar этого пользователя.

## Сопоставление
- Нормализация: регистр, ё → е, вырезание feat, remaster и скобок.
- Кандидат проходит, только если его нет в библиотеке, пуле, резерве и чёрном списке.
- Лайвы, караоке, минусовки и каверы отсеиваются, если само семя не такое.

## Скоринг
- Базовая формула: Σ (вес источника × схожесть × вес семени).
- Бонус ×1.3 за каждый следующий источник, предложивший тот же трек.
- Не больше двух треков одного артиста за одно пополнение. Доля новых для пользователя артистов настраивается.
- Артисты с reject получают штраф.
- Веса источников самонастраиваются по доле promote: старт 1.0 у всех, сглаживание, чтобы источник не обнулился от
  трёх неудач.

## Пополнение
Раз в сутки по крону топ-N уходит в очередь bodrod по существующей цепочке (Яндекс → slskd → YouTube → Lidarr).
Сначала берётся то, что уже лежит в резерве.

## Приложение
В настройках bodrod каждый источник включается и выключается отдельно и получает свой вес, как сейчас сделан
переключатель Яндекса. Когда движок заработает, Explo станет лишним: плейлисты LB движок забирает сам.
