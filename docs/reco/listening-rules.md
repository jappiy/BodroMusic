# Правило засчитывания прослушиваний и пропусков (с app 0.30.0)

Три разных потребителя — три разных правила. Всё хранится по учётке (Room — по `accountId`, Navidrome — по пользователю).

## 1. Скроббл во внешние сервисы (Last.fm, ListenBrainz) и счётчик Navidrome

`core/domain/.../scrobble/ScrobbleTracker.kt`, `ScrobblePolicy` — стандарт Last.fm / ListenBrainz:

- трек длиннее 30 с;
- реально прослушано (без перемотки вперёд и паузы) ≥ 50 % длительности **или** ≥ 4 мин;
- один скроббл за проигрывание; повтор трека — новое проигрывание.

Приложение шлёт `scrobble(submission=true)` в Navidrome, тот увеличивает `playCount` (статистика «Коллекции») и
пересылает в Last.fm / ListenBrainz (`ND_LASTFM_*`, `ND_LISTENBRAINZ_*`). Частичные прослушивания наружу не уходят.
В начале трека — только «сейчас играет» (`submission=false`). Офлайн — очередь `pending_scrobbles`.

## 2. Итог проигрывания для рекомендаций — `ListenRules`

`core/domain/.../scrobble/ListenRules.kt`, считается в `ScrobbleTracker.finish` → `PlaySession.outcome`,
пишется в историю `play_history.outcome` (Room v3) вместе с `durationMs` и контекстом.

| Итог | Условие | Сигнал |
|---|---|---|
| `Full` — полное | прослушано ≥ 50 % или ≥ 4 мин | позитив: исполнитель и жанр поднимаются в профиле вкуса |
| `Partial` — частичное | всё остальное, в т. ч. 20–50 %, пауза, остановка | нейтрально: только «играл недавно» (кулдаун 7 дней), вкус не меняется |
| `EarlySkip` — ранний пропуск | пользователь переключил, прослушав < 30 с **или** < 20 % | слабый негатив (ниже) |
| дизлайк | «Не нравится» | жёсткое исключение: никогда в волне |

Записи истории до 0.30.0 без `outcome`: `skippedEarly = true` → ранний пропуск, иначе — полное.

## 3. Как ранний пропуск влияет на волну

`WaveProfileBuilder` (профиль) → `WaveEngine` («Моя волна», миксы) и `TrackWavePlanner` («Волна по треку»):

- **Кулдаун, а не приговор.** Пропущенный трек не появляется в волне `waveSkipCooldownDays` дней (по умолчанию 7,
  «Настройки → Волна → Пропущенный трек в волне»: 1 / 3 / 7 / 14 / 30), потом может вернуться.
- **Вес трека** понижается (×0,3) только после 3 ранних пропусков без единого полного прослушивания после них.
  Полное прослушивание «прощает» прежние пропуски.
- **Контекст** (`PlayContext`, по источнику очереди в момент окончания трека):
  - `Wave` — «Моя волна», «Волна по треку», режимы, «Похожие по звучанию»: вес пропуска 1;
  - `Own` — свой плейлист, альбом, «Мне нравится», исполнитель: вес 0,1, кулдауна и счётчика пропусков трека нет;
  - `Other` — поиск, чарты, прочее: вес 0,5.
- Исполнитель и жанр: взвешенная сумма ранних пропусков снижает вес (`1 / (1 + 0,15·пропуски)`, не ниже 0,25).
  «Сбросить статистику пропусков» — пропуски раньше этой отметки не учитываются.
- Серверная волна bodrod получает события сессии: `skip` — только ранний пропуск, `complete` — только полное
  прослушивание; частичное не отправляется.
- Пул «На пробу» (`POST /api/v1/feedback`): `completed` — полное, `skipped` — ранний пропуск, частичное — без события
  (до 0.30.0 «полным» считалось ≥ 80 %, всё остальное было «пропуском»).

## Как было до 0.30.0

- Скроббл — то же правило (50 % / 4 мин, трек > 30 с).
- Ранний пропуск — переключение в первые 30 с; трек сам по себе не наказывался и не охлаждался (мог прийти снова
  в следующей порции), но каждый пропуск навсегда (до сброса) понижал исполнителя и жанр — в том числе пропуски
  в своём плейлисте.
- Любое прослушивание ≥ 3 с без пропуска считалось «прослушано»: поднимало исполнителя и жанр и уводило трек
  на 7-дневный кулдаун.
- Пул «На пробу»: ≥ 80 % — `completed`, иначе `skipped`.
