- **Дата:** 2026-10-20
- **Версии:** bodrod 0.8.0
- **Релиз с APK:** не требуется — только сервер
- **Образ bodrod:** `ghcr.io/jappiy/bodromusic-server:<хеш коммита>` (см. раздел «Что нужно сделать на сервере»)
- **Статус:** реализовано, тесты на поддельном аккаунте; с настоящим Яндексом не проверялось

## Задание

ТЗ владельца «Рекомендательная система и чарты» (`docs/reco/`), задача 1 —
[`docs/reco/01-yandex-archive.md`](../reco/01-yandex-archive.md): до 20.11.2026 (конец подписки Плюс) собрать с двух
аккаунтов Яндекса всё, что пригодится движку рекомендаций, и предзакачать лучших кандидатов в резерв.

## Решения владельца

- Все пять задач ТЗ делаются по очереди, по релизу на задачу (задания 009–013).
- Дефолтные числа — стартовые, все настраиваются.

## Что сделано

Сервер, пакет `server/bodrod/reco/`:
- `store.py` — таблицы: `y_tracks`, `y_artists`, `y_albums`, `y_likes` (лайки/дизлайки по пользователю), `reco_edges`
  (семя → кандидат: тип `similar` / `wave` / `artist_similar` / `playlist` / `history` / `chart` / `new_release`, ранг,
  `seen_count`), `harvest_done` (продолжение разовых проходов), `user_blocklist` (чёрный список пользователя, со
  сроком), `pool_tracks` + `pool_owners` (общий трек пула/резерва и его владельцы — пригодятся в задаче 2).
- `yandex_account.py` — клиент аккаунта поверх yandex-music: пауза ~1 с, повтор с бэкоффом при сетевых сбоях, ошибка
  доступа → `AccessDenied`. Волна читается только `rotor_station_tracks` (без radioStarted/skip-фидбека).
- `harvest.py` — `YandexHarvester`: проход раз в 10 минут по каждому аккаунту, сборщики со своими сроками (таблица в
  `server/README.md`). Волна — 24 режима по кругу (favorite/discover/popular × active/fun/calm/sad ×
  russian/not-russian), настройки аккаунта сохраняются до прогона и восстанавливаются после. Сырые ответы —
  `<YANDEX_ARCHIVE_DIR>/<пользователь>/<дата>/<тип>.json`. Ошибка доступа отключает только свой сборщик (повтор через
  7 дней). Предзакачка: кандидаты по частоте в `wave` + `similar`, без лайкнутых, уже имеющихся в библиотеке, пуле,
  резерве и чёрных списках, без ремиксов/лайвов/каверов → `RESERVE_DIR` (`.ndignore` с шаблоном `*`), до 500 на
  пользователя, скачивание токеном самого пользователя.
- `keys.py` — ключ трека: основной исполнитель + название без скобок, feat, remaster, в одном алфавите.
- `library.py` — индекс библиотеки по ключам из БД Navidrome (раз в час), треки пула отделены по пути.
- `config.py` — `YANDEX_ACCOUNTS` (или файлы `/secrets/yandex_accounts/<пользователь>`), `YANDEX_ARCHIVE_DIR`,
  `HARVEST_*`, `RESERVE_*`, `DISCOVERY_DIR`.
- `main.py` — `GET /api/v1/reco/harvest`, `POST /api/v1/reco/harvest/run` (только админ).
- `maintenance.py` — регламент не трогает `_discovery` и `_reserve`.
- `Placer.place(..., root=)` — раскладка не только в библиотеку.
- `Store` — общие методы `execute` / `query` для модулей со своими таблицами.

Тесты: `server/tests/test_harvest.py` (7): полный проход, продолжение похожих после обрыва, отключение одного сборщика
при ошибке доступа, предзакачка (частота, исключения, `.ndignore`, без повторов), без Плюса, общее только с первого
аккаунта.

## Что нужно сделать на сервере

**До 20 ноября 2026.**
1. Токены обоих аккаунтов (как `yandex_music_token`) — файлами `/volume1/docker/secrets/yandex_accounts/<имя
   пользователя Navidrome>` (папка монтируется в bodrod как `/secrets`).
2. Архив — на volume2: смонтировать, например, `/volume2/music-archive/yandex:/archive` и задать
   `YANDEX_ARCHIVE_DIR: /archive`.
3. Обновить образ bodrod на 0.8.0, посмотреть `docker logs bodrod` («Архив Яндекса: аккаунты …»).
4. Через час проверить `GET /api/v1/reco/harvest` (или экран в приложении в следующих версиях): у сборщиков есть
   `lastAt`, в `/volume2/music/_reserve` появляются файлы.
