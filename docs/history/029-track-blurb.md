# 029 — Короткий текст о треке/исполнителе: только русский, законченный, без обрезки

- **Дата:** 2026-10-24
- **Версии:** bodrod 0.21.0, приложение 0.27.0
- **Релиз с APK:** https://github.com/jappiy/BodroMusic/releases/tag/v0.27.0 (CI зелёный на `11efb42`, Release #21, APK в `dist`)
- **bodrod:** 0.21.0 установлен на NAS 2026-10-24 по `docs/DEPLOY.md`
- **Статус:** реализовано; pytest; проверено на настоящем API Яндекс Музыки с ПК владельца; на телефоне не проверено

## Задание

Текст под «таблеткой» бывал английским («This is Ghost's leading single…») и обрезанным («…однако большую …»).
Нужно: только русский, короткий законченный текст в 2–3 строки (~110 символов), без многоточий. Формировать на
сервере с кэшем на трек/исполнителя: русские описания (Яндекс Музыка, вступление ru.wikipedia), затем факты метаданных
и Last.fm по шаблону («Ведущий сингл альбома «Meliora» (2015)»); из длинного — одно законченное предложение; нет —
шаблон; нет и его — блок не показывать. Клиент проверяет, что текст влезает при текущем шрифте, иначе — короче
или скрыть. Пока подбирается — «Собираю интересное…» (как на эталоне).

## Что выяснено

- С ПК владельца (и, вероятно, с NAS) **ru.wikipedia недоступна** — запрос висит до тайм-аута.
- Яндекс Музыка отдаёт описание исполнителя на русском даже без токена (`artists_brief_info`): «Шведская рок-группа,
  основанная в 2006 году в Линчёпинге.», «Американский певец, автор песен и танцор.».

## Что сделано

- `server/bodrod/metadata/facts.py` (переписан): источники по порядку — статья о песне в ru.wikipedia, описание
  исполнителя в Яндексе (`YandexMusicApi.artist_description`), вступление статьи об исполнителе в ru.wikipedia,
  русская биография Last.fm, шаблоны («Трек из альбома «X» (2015)», «Жанр — пост-панк» по словарю тегов,
  «У X больше 1,2 млн слушателей на Last.fm»). Текст: без HTML, ссылок и скобок (даты, «англ. …»); предложения
  делятся с учётом сокращений («1981 г.», «В. Цой»); берутся только законченные русские предложения ≤ лимита;
  длинное предложение сокращается по запятой до законченной фразы, если хвост — придаточное или оборот
  («X — певец, один из…» → «X — певец.»); описание без точки получает точку.
- Ответ `/api/v1/artists/facts?artist&title&album&year&maxChars=110`: `fact` + `variants` (до 4, от лучшего к
  запасным), `source`. Кэш — в памяти на сутки и в таблице `track_blurbs` на 30 дней; сбой не кэшируется.
  ru.wikipedia после сбоя не опрашивается 30 минут (тайм-аут 4 с), чтобы ответ не ждал.
- Клиент: тексты приходят через `TrackInfoRepository` (грузятся при старте трека, фильтр «только русский» — на
  случай старого сервера). `TrackBlurb` в `WaveHome.kt`: место ровно под 3 строки; `TextMeasurer` выбирает первый
  вариант, который целиком помещается при текущей ширине и шрифте; ни один — блок пуст. Пока грузится — значок-
  искра и мерцающее «Собираю интересное…», итог появляется плавно.
- Тесты: `server/tests/test_facts.py` (английский не берётся, сокращение длинного до фразы, сокращения в тексте,
  шаблоны, порядок источников и кэш в базе, Яндекс при недоступной Википедии), `GlowRhythmTest` (подбор под 3 строки,
  фильтр русского).

## Решения

- Варианты отдаются списком сразу, а не повторным запросом «короче»: клиент выбирает подходящий без лишнего
  круга к серверу.
- Английские описания не переводятся (нет переводчика без внешних сервисов) — вместо них шаблонные фразы.
