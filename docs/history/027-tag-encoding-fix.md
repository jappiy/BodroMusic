# 027 — Ночная проверка и исправление битой кодировки тегов (bodrod)

- **Дата:** 2026-10-24
- **Версии:** bodrod 0.21.0, приложение 0.27.0 (экран отчёта)
- **Релиз с APK:** https://github.com/jappiy/BodroMusic/releases/tag/v0.27.0 (CI зелёный на `11efb42`, Release #21, APK в `dist`)
- **bodrod:** 0.21.0 установлен на NAS 2026-10-24 по `docs/DEPLOY.md` (только код, база `9f5de2f` не менялась)
- **Статус:** реализовано; pytest (детектор на парах из задания, запись MP3/FLAC/OGG/M4A, регламент, откат, пробный
  режим); на реальной библиотеке не проверено

## Задание

У части треков в названии, исполнителе, альбоме, жанре — мусор: «íè÷åãî íå èñ÷åçàåò», «Ñåêðåò», «Ìàøèíà
Âðåìåíè», «Ðîê» (русский в Windows-1251, прочитанный как Latin-1/CP1252). Добавить в ночной регламент шаг
«Исправление кодировки тегов»: обнаружение (title, artist, album, albumartist, genre, composer), перекодирование
`cp1252 → cp1251` (запасной вариант latin-1), без ложных срабатываний на «Beyoncé», «Mötley Crüe», «Sigur Rós»;
запись в файл (MP3 — ID3v2.4 UTF-8, ID3v1 удалить; FLAC/OGG — Vorbis; M4A — атомы); бэкап исходных тегов для отката;
невосстановимое — AcoustID/MusicBrainz, иначе «Требует ручной проверки»; пересканирование Navidrome; в отчёте — сколько
исправлено, «было → стало», что на ручную проверку; та же проверка при импорте новых загрузок; юнит-тесты на примерах.

## Что сделано

- `server/bodrod/encoding.py`:
  - `repair(s)`: строка без кириллицы; каждое слово с не-ASCII символами после перекодирования состоит только из
    кириллических букв (латиница вперемешку с кириллицей — «Beyoncй», «Mцtley» — значит, строка настоящая);
    ≥ 2 букв; доля гласных 15–80 %; нет слов на «ъ»/«ь». ASCII-слова рядом («feat.», «2») остаются как есть;
  - `suspicious` / `unrecoverable`: «??», символ замены U+FFFD или ≥ 3 букв À–ÿ при доле ≥ 50 % — и не
    восстанавливается → ручная проверка;
  - `read_values` / `write_values` (mutagen easy-интерфейс; у MP3 без ID3v2 читается ID3v1; MP3 сохраняется
    `v1=0, v2_version=4` — ID3v1 удаляется, новые кадры в UTF-8);
  - `EncodingJournal` — таблица `tag_encoding_fixes` (путь, было, стало, источник, время, отмена); `revert()`;
  - `acoustid_lookup` — `fpcalc` + api.acoustid.org (оценка ≥ 0,9), если есть `fpcalc` и `ACOUSTID_API_KEY`.
- `maintenance.py` — шаг идёт **первым** (дубли и теги дальше сравниваются по исправленным названиям):
  каждый файл (кроме папок Lidarr и файлов, где исправление откатили) проверяется раз в 30 дней или после изменения;
  исправленное пишется в файл, исходное — в журнал, в отчёт — «Исправлена кодировка тегов — название: «Ñåêðåò» →
  «Секрет»»; невосстановимое название/исполнитель/альбом — AcoustID, затем цепочка `TAG_PROVIDERS` (MusicBrainz и
  др.) по имени файла и папке; не нашлось — причина `encoding_manual` («требует ручной проверки»). После прохода —
  пересканирование Navidrome (общее для регламента). Пробный режим только пишет «Будет исправлена…».
- Сводка `GET /maintenance/summary`: `fixed.encoding_fixed`, `unresolved.encoding_manual`, `encoding` (до 300
  исправлений последнего запуска: путь, поля «было → стало», источник, отменено ли), `encodingManual` (пути).
  Откат: `POST /api/v1/maintenance/encoding/{id}/revert` (админ).
- Импорт: `placement.place_file` после записи тегов вызывает `fix_encoding` — так исправляется всё, что идёт через
  bodrod (Яндекс, slskd, YouTube, пул рекомендаций, чарты).
- Приложение: «Настройки → Обслуживание библиотеки» — «Исправленная кодировка тегов: N» со строками «было → стало»
  и «Отменить», «Битая кодировка — нужна ручная проверка: N» с путями (`MaintenanceScreen.kt`).
- `config.py`: `ACOUSTID_API_KEY` (или `/secrets/acoustid_api_key`).
- Тесты: `server/tests/test_encoding.py` (30: пары из задания, ложные срабатывания, ID3v1 → ID3v2.4 UTF-8,
  FLAC/OGG/M4A, ручная проверка, регламент с журналом и откатом, пробный режим).

## Решения

- Папки Lidarr не трогаются (правило задания 019): Lidarr пишет теги MusicBrainz, битой кодировки там не бывает, а
  менять его файлы регламенту запрещено. Импорт Lidarr идёт мимо bodrod — проверяется ночью только вне его папок.
- `fpcalc` (Chromaprint) в базовом образе нет, а новая база = новый `requirements`/apt и скачивание на NAS. Поэтому
  AcoustID включится, только когда появятся `fpcalc` и ключ; сейчас невосстановимые строки ищутся по имени файла и
  папке через уже работающую цепочку тегов (MusicBrainz, Яндекс, Deezer…).
- Регламент в боевом режиме (`MAINTENANCE_DRY_RUN=false`): шаг покрыт тестами до установки; любое исправление
  откатывается из приложения.

## Что нужно сделать на сервере
