# 005 — Регламент обслуживания библиотеки, популярное исполнителя, быстрый старт воспроизведения

- **Дата:** 2026-10-16
- **Версии:** приложение 0.11.0 (`versionCode 11`), bodrod 0.4.0
- **Релиз с APK:** локально собраны `dist/BodroMusic-0.11.0.apk` и `-debug.apk`; релиз на GitHub — запустить Release вручную (версия `0.11.0`)
- **Образ bodrod:** `ghcr.io/jappiy/bodromusic-server:<хеш коммита с bodrod 0.4.0>` — появится после зелёного `server.yml`
- **Статус:** реализовано; локально — сборка debug/release, unit-тесты, lint, ktlint, detekt, pytest + ruff.
  На телефоне и на реальном сервере не проверено.

## Задание

1. Сервер:
   - регламентное задание, которое проходит по трекам и проверяет теги, картинки, альбомы — корректность метаданных;
   - регламент, который ищет дубли альбомов, дубли песен, подозрительно короткие файлы и объединяет или удаляет их;
     отчёт — в клиенте, в настройках, отдельной вкладкой;
   - задержка при воспроизведении новой, ещё не кэшированной песни; в других приложениях листание без задержки —
     можно ли улучшить.
2. Вкладка исполнителя:
   - не уверен, что популярные треки берутся из популярных Яндекс Музыки;
   - первый список — скачанные популярные песни; добавить второй — нескачанные популярные (тоже из Яндекса)
     с возможностью поставить на загрузку.
3. Прочее: удалённый трек не показывать в «Любимом»; теги «Моей волны» неудобно расположены и неинтуитивно
   прокручиваются; обводка дизлайка синяя, а не красная; кнопка отмены у загрузки по исполнителю
   («начал отслеживать автора»); вернуть кнопку «Очередь» в нижнюю панель с «Повтором» и «Перемешать».

## Решения владельца

- Дубли и короткие файлы — автоматически, но в **карантин на 30 дней** с кнопкой «Вернуть» в приложении.
- Теги и обложки — исправлять автоматически, **если совпадение надёжное**; спорное — только в отчёт.
- Теги «Моей волны» — **перенос строк** с подписями групп, склейка дублей жанров, у жанров — топ-8 и «Ещё».
- Трек, видимый в «Любимом», был удалён **через «На удаление»**.
- Разрешено скачать портативный JDK 17 (`C:\tools\jdk17`) для локальной сборки.

## Что выяснено

- **Популярное в глобальном поиске** уже из Яндекса: `/artists/{id}/tracks` отдаёт треки ровно в порядке
  `/artists/{id}/track-ids-by-rating` и `brief-info.popularTracks` (проверено запросом к API). А **на экране
  исполнителя** «Популярные треки» были из своей истории + `getTopSongs` Navidrome (Last.fm), не из Яндекса.
- **Удалённый трек в «Любимом»:** лайк в Navidrome — запись `annotation` по id трека; после удаления файла
  `getStarred2` может продолжать его отдавать, а кэш лайков в Room вообще не знал об удалении.
- **Задержка старта:** ExoPlayer по умолчанию ждёт 2,5 с буфера (`bufferForPlaybackMs`), следующий трек очереди
  начинает грузиться только у конца текущего. Перекодированный поток Navidrome без `Content-Length` не перематывается.

## Что сделано

- Сервер (bodrod 0.4.0):
  - `bodrod/maintenance.py` — `MaintenanceService`: расписание (`MAINTENANCE_AT`), короткие/обрезанные файлы,
    дубли треков, дубли альбомов (перенос в одну папку), теги и обложки по каталогу, карантин (`.ndignore`,
    очистка через `QUARANTINE_DAYS`), возврат, таблица замен для переноса лайков, пробный режим. Файлы папок
    Lidarr не трогает. Общая блокировка файлов с «На удаление» (`CleanupService(lock=…)`).
  - `db.py` — таблицы `maintenance_runs`, `maintenance_actions`, `quarantine`, `replacements`, `maintenance_checked`.
  - `navidrome_db.py` — поля `album_artist`, `disc_number`, `track_number`, `has_cover_art`; `present_ids`,
    `ids_by_path`, `annotation_counts`; пути Navidrome собираются через `posixpath` (на Windows тесты падали).
  - `main.py` — `GET /api/v1/artists/popular`, `POST /api/v1/library/check`, `/api/v1/maintenance*`;
    `info.maintenance`. `metadata/discover.py` — `artist_popular`. `config.py` — переменные `MAINTENANCE_*`,
    `QUARANTINE_*`.
  - Отмена заявки на исполнителя: `LidarrClient.stop_artist` (мониторинг снят, загрузки убраны из очереди,
    файлы остаются), вызывается из `Worker.cancel`.
- Приложение (0.11.0):
  - `core:downloads` — модели и методы: `ArtistPopular`, `LibraryCheck`, `MaintenanceStatus/Run/Action`.
  - Воспроизведение: `PlaybackService` — `DefaultLoadControl` со стартом после 0,5 с буфера;
    `playback/StreamPrefetcher.kt` — начало (1,5 МБ) следующих двух треков очереди скачивается в кэш стрима
    (`StreamDataSourceFactory.prefetch`, `CacheWriter`, тот же ключ кэша); `SubsonicClient.streamUrl` —
    `estimateContentLength=true` для перекодированного потока.
  - Исполнитель — `ui/screens/artist/ArtistScreen.kt`: популярное из Яндекса через bodrod — «Популярные треки»
    (есть в библиотеке, порядок Яндекса) и «Популярное, которого нет в библиотеке» (`DiscoverTrackRow`, загрузка,
    статус заявки). Без bodrod — как раньше.
  - «Любимое» — `data/downloads/LikedCheck.kt` (при обновлении «Коллекции» и «Любимого»: удалённые убираются,
    лайк переносится на оставшуюся копию), `ReactionRepository.forget`; «На удаление» сразу убирает удалённое из кэша.
  - «Моя волна» — `ui/screens/wave/WaveScreen.kt`: группы «Настроение / Жанр / Эпоха», `FlowRow`, вертикальная
    прокрутка экрана; `WaveRepository.topGenres` — без дублей по регистру.
  - Плеер — `FullPlayerScreen.kt`: дизлайк синий (`DislikeBlue`), «Очередь» в нижней панели (`open-queue`),

  - Поиск — `Discover.kt`: у исполнителя в загрузке кнопка отмены (`discover-cancel-artist`).
  - Настройки — `ui/screens/settings/MaintenanceScreen.kt`: «Обслуживание библиотеки».

## Что нужно сделать на сервере

Обновить образ в проекте `bodrod` (DSM → проект → YAML) и пересобрать. Новых томов не нужно: регламент
использует уже подключённые `NAVIDROME_DB` и `/music` (на запись). Для первого запуска рекомендуется пробный режим:
```yaml
image: ghcr.io/jappiy/bodromusic-server:<хеш>
environment:
  TZ: Europe/Moscow              # время запуска регламента — по часовому поясу контейнера
  MAINTENANCE_DRY_RUN: "true"    # первый прогон — только отчёт; потом убрать
  # MAINTENANCE_AT: "04:00"
```
Затем в приложении: **Настройки → Обслуживание библиотеки → Запустить сейчас**, просмотреть отчёт,
убрать `MAINTENANCE_DRY_RUN` и пересобрать проект.
