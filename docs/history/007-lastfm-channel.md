# 007 — Last.fm как дополнительный канал распознавания

- **Дата:** 2026-10-19
- **Версии:** приложение 0.13.0 (`versionCode 13`), bodrod 0.6.0
- **Релиз с APK:** https://github.com/jappiy/BodroMusic/releases/tag/v0.13.0
- **Образ bodrod:** `ghcr.io/jappiy/bodromusic-server:6425a2c`
- **Статус:** реализовано; CI зелёный на `6425a2c` (Android с эмулятором, сервер — 90 тестов pytest, ruff); с настоящим Last.fm не проверялось — нет ключа API

## Задание

«Добавь распознавание с Last.fm везде, где это необходимо, как дополнительный канал. Он может быть иногда
недоступен — тогда должны работать остальные. Может ли Last.fm скробблить данные, чтобы выдавать рекомендации?»

## Решения

- Last.fm — **последний** источник в каждой цепочке по умолчанию (дополнительный канал, а не замена Яндексу).
  Порядок меняется переменными `COVER_PROVIDERS`, `TAG_PROVIDERS`, новая — `DISCOVER_PROVIDERS`.
- Без ключа `LASTFM_API_KEY` Last.fm нигде не используется, поведение как в 0.5.0 (версия цепочки та же —
  отметки «не найдено» не сбрасываются).

## Что выяснено

- «Распознавание» (поиск данных о треке по исполнителю/названию) в проекте — только в bodrod:
  цепочки тегов и обложек регламента (`metadata/lookup.py`), глобальный поиск и «Популярные треки» исполнителя
  (`metadata/discover.py`). Клиент сам каталоги не опрашивает — ему нужна только подпись источника.
- API Last.fm: без ключа отвечает ошибкой 6. Ошибка 6 — это и «не найдено»: сбоем не считается.
  Вместо пустой картинки Last.fm отдаёт заглушку (хеш `2a96cbd8…`) — отбрасывается. Размер `770x0` существует.
  В `track.search` и `artist.getTopTracks` длительности нет; в `track.getInfo` — есть (мс).
- **Скробблинг и рекомендации.** Last.fm копит историю прослушиваний и по ней строит рекомендации (на сайте),
  а через API отдаёт «похожие» (`track.getSimilar`, `artist.getSimilar`) и топы пользователя. Скробблить туда
  умеет сам Navidrome: на сервере нужны `ND_LASTFM_APIKEY` и `ND_LASTFM_SECRET`, а каждый пользователь связывает
  свою учётку в веб-интерфейсе Navidrome (профиль → Last.fm). Приложение уже отправляет `scrobble` в Navidrome,
  так что прослушивания с телефона пойдут в Last.fm без изменений клиента. С этим же ключом Navidrome начинает
  отвечать на `getSimilarSongs2` / `getTopSongs` / `getArtistInfo2` — «Моя волна» их уже подмешивает как бонус
  (ТЗ, раздел про волну), а экран исполнителя использует `getTopSongs` как запасной вариант.

## Что сделано

- Сервер:
  - `server/bodrod/metadata/lastfm.py` — `LastFmClient` (пауза 0,25 с между запросами; «предохранитель»: 3 сбоя
    подряд — тайм-аут, HTTP-ошибка, ошибка лимита — и 5 минут запросы к Last.fm отклоняются сразу, без сети),
    `LastFmLookup` (теги и обложки: `track.getInfo` с `autocorrect`, при отсутствии обложки — `album.getInfo`),
    `LastFmProvider` (глобальный поиск `track.search` + `artist.search`, популярное — `artist.getTopTracks`).
  - `config.py` — `LASTFM_API_KEY` (или `/secrets/lastfm_api_key`), `DISCOVER_PROVIDERS`; `lastfm` добавлен в
    конец цепочек по умолчанию. `metadata/lookup.py` — `build_chain(..., lastfm)`, название «Last.fm» в отчёте.
  - `main.py` — каталоги поиска собираются по `DISCOVER_PROVIDERS`.
  - `maintenance.py` — отключённый источник пропускается без расхода `MAINTENANCE_CATALOG_LIMIT`.
- Приложение: `ui/screens/search/Discover.kt` (`sourceName` — «Last.fm», стал общим), `ui/screens/artist/ArtistScreen.kt`
  (подпись каталога у «Популярное, которого нет в библиотеке» берётся из ответа), `strings.xml`.
- Тесты: `server/tests/test_lastfm.py` (12): разбор ответов, заглушка картинки, «не найдено» ≠ сбой, предохранитель
  и восстановление, ошибка лимита, цепочка без ключа, регламент не тратит бюджет, фолбэк поиска на Last.fm,
  популярное из Last.fm, поиск работает при упавшем Last.fm, ключ из `/secrets`.

## Что нужно сделать на сервере

1. Получить ключ: https://www.last.fm/api/account/create (бесплатно).
2. Положить его в `/secrets/lastfm_api_key` (как `discogs_token`: права 600, владелец 1027) и обновить образ bodrod
   до 0.6.0. В логе при старте — «Каталоги поиска: yandex, deezer, lastfm» и `lastfm` в цепочках обложек и тегов.
3. Для скробблинга и рекомендаций (по желанию): тот же ключ и секрет — в Navidrome (`ND_LASTFM_APIKEY`,
   `ND_LASTFM_SECRET`), затем каждый пользователь связывает Last.fm в веб-интерфейсе Navidrome.

## Что осталось / проверить

- Проверить с настоящим ключом: глобальный поиск при отключённых Яндексе и Deezer, лог предохранителя.
- Возможное продолжение: рекомендации «чего нет в библиотеке» по Last.fm (`track.getSimilar` от лайков) в «Моей
  волне» с кнопкой загрузки.

## Продолжение 2026-10-19: подпись APK (0.13.1)

- **Проблема владельца:** обновление не ставится поверх старой версии («Приложение не установлено»), не первый раз.
- **Причина:** release подписывался debug-ключом, а на раннере GitHub он генерируется заново при каждом запуске —
  у каждого релиза своя подпись (0.13.0 с GitHub — `648f26d8…`). APK 0.10–0.12 в `dist` собраны на компьютере
  владельца и подписаны его `~/.android/debug.keystore` (`c5146426…`). Android не обновляет приложение с другой подписью.
- **Решение владельца:** постоянный ключ — тот, что на компьютере владельца (обновление с 0.10–0.12 без удаления).
- **Сделано:** секрет репозитория `SIGNING_KEYSTORE_B64` (keystore в base64, зашифрован GitHub); `release.yml`
  раскладывает его в файл и передаёт Gradle через `BODRO_KEYSTORE` (явный `signingConfigs.bodro` для debug и
  release; первая попытка — подмена `~/.android/debug.keystore` — на раннере не сработала, проверка подписи
  поймала чужой ключ `f6affeb4…` и релиз не опубликовала), без секрета падает, а перед публикацией сверяет отпечаток
  сертификата каждого APK с `c5146426…94de62`. Комментарий в `app/build.gradle.kts`, правило в HANDOFF 0.2.
- Релиз: https://github.com/jappiy/BodroMusic/releases/tag/v0.13.1 (CI зелёный на `a9eab7f`), оба APK подписаны
  `c5146426…`, лежат в `dist/`.
- Кто поставил APK с GitHub (0.7–0.9, 0.13.0), должен один раз удалить приложение; дальше обновления встают поверх.
