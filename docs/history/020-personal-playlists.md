# 020 — Персональные плейлисты (этап 1 из 5)

- **Дата:** 2026-10-23
- **Версии:** приложение 0.22.0 (`versionCode 23`), bodrod 0.17.0
- **Релиз с APK:** https://github.com/jappiy/BodroMusic/releases/tag/v0.22.0
- **bodrod:** 0.17.0, ставится по `docs/DEPLOY.md` (robocopy `server` → «Остановить» → «Создать»); база не менялась
- **Статус:** реализовано; покрыто unit-тестами и pytest; на сервере и телефоне не проверено

## Задание

Большое задание владельца из пяти этапов (персональные плейлисты, адаптивная вёрстка, новая главная «Моя волна»,
режимы волны и анализ, полноэкранный плеер со скроллом). Этап 1 — плейлисты:

- разобраться, общие плейлисты или у каждого свои: что отдаёт `getPlaylists` (owner, public), не создают ли
  приложение, bodrod или Explo плейлисты от одного (админского) аккаунта, не смешивается ли локальный кэш между
  аккаунтами, кто владелец плейлистов, импортированных из `.m3u` / `.nsp`, и настройка их видимости;
- плейлист принадлежит создателю, новые — от текущего аккаунта приватными; владелец создаёт, переименовывает,
  меняет состав и порядок, удаляет; чужие приватные не видны; «Поделиться» = публичный, «Перестать делиться» =
  приватный; чужие публичные — раздел «Общие» с именем владельца, только чтение, «Сохранить себе»;
- локальная БД и кэш разделены по аккаунту (сервер + пользователь);
- плейлисты не у того владельца автоматически не трогать, вывести список — решает пользователь.

Этапы 2–5 — задания 021–024.

## Что выяснено

1. **`getPlaylists` у администратора отдаёт все плейлисты сервера, включая чужие приватные.** В Navidrome
   (`persistence/playlist_repository.go`, `userFilter`) для админа фильтр пустой, для обычного пользователя —
   `public OR owner_id = я`. Приложение показывало их все; редактировать чужие не давало (`isEditableBy`),
   но видно было всё. Отсюда впечатление «плейлисты общие». Поле `owner` Navidrome отдаёт всегда.
2. **Приложение** создаёт плейлисты `createPlaylist` от текущей учётки — владелец правильный. Navidrome создаёт
   их приватными; теперь приложение дополнительно ставит `public=false`, если сервер вернул иное.
3. **bodrod** сам плейлисты через API не создаёт. Но выгрузка из Яндекса (`sources/export.py`, с 0.7.0) писала
   `.m3u8` в `library/Плейлисты Яндекса/`, а Navidrome делает владельцем импортированного из файла плейлиста
   **первого администратора** — независимо от того, чей это Яндекс. Плюс все выгрузки складывались в одну папку.
4. **Импорт `.m3u` / `.nsp`**: владелец — первый администратор; видимость — `ND_DEFAULTPLAYLISTPUBLICVISIBILITY`
   (по умолчанию `false` — приватные). В YAML проекта `bodromusic` переменная не задана, значит такие плейлисты
   приватные у первого админа и второй пользователь их не видит вовсе.
5. **Explo** создаёт плейлисты учёткой из своего `.env` (`SYSTEM_USERNAME`). Прочитать `.env` на NAS агенту
   не дали (правило авто-режима «чтение боевых данных»), поэтому какая учётка у `explo-wife` — не проверено:
   если там админ, подборки жены принадлежат админу. Это видно в новом отчёте (причина «Похоже на подборку Explo»).
6. **Локальные данные.** Room (лайки, дизлайки, история, очередь, офлайн-скробблы, поиск, события пула) разделён
   по `accountId`; учётка = логин + адреса сервера. Кэши в памяти (`LibraryRepository`, `PoolRepository`,
   `ReactionRepository`, заявки) привязаны к учётке или сбрасываются при смене. **Утечка была одна:** настройки
   волны (характер, настроение, доля «незнакомого», сброс статистики пропусков) и чартов (порядок, скрытые) лежали
   в DataStore общими для всех учёток. Исправлено.
7. Реальный список плейлистов сервера агент не получил — чтение `navidrome.db` с NAS тоже запрещено правилом
   авто-режима. Вместо этого сделан отчёт в приложении (ниже): его нужно открыть администратору.

## Что сделано

- Модель: `Playlist.accessFor(username)` → `PlaylistAccess.Own / Shared / Hidden` (`core/model/.../Library.kt`).
- Subsonic: `updatePlaylist(public = …)`, `replacePlaylistSongs` — `createPlaylist` с `playlistId` заменяет состав
  целиком, так меняется порядок (`core/subsonic/.../SubsonicClient.kt`).
- `PlaylistRepository` (`data/repository/SmallRepositories.kt`): `playlists()` — свои и общие (чужие приватные
  отброшены, в т. ч. при открытии по ссылке), `myPlaylists()`, `create` (приватный), `createWithIds`, `saveCopy`,
  `setShared`, `reorder`. Главная (`LibraryRepository.home`) тоже не показывает чужие приватные.
- Экраны (`ui/screens/playlist/PlaylistScreens.kt`): разделы «Мои» и «Общие»; у своего — «Общий / Только мой»,
  меню «Переименовать / Поделиться или Перестать делиться / Удалить»; у общего — владелец и «Сохранить себе».
  Экран плейлиста: то же меню, «Изменить порядок» (стрелки вверх/вниз, «Готово» сохраняет), удаление закрывает экран.
  «Добавить в плейлист» по-прежнему показывает только свои.
- Настройки волны и чартов — по учётке: ключи DataStore `wave_mood@<accountId>` и т. п., старые общие значения —
  запасные (`data/settings/SettingsRepository.kt`). Значения пишутся под ту учётку, для которой прочитаны, —
  при переключении учётки настройки прежней не перетекают в новую. Заодно добавлены поля для этапа 3:
  `backgroundAnimation`, `waveModeId`.
- Отчёт «Плейлисты на сервере» (настройки, для администраторов, `ui/screens/settings/PlaylistAuditScreen.kt`):
  число плейлистов по владельцам и список «Проверить владельца» с причиной: импорт из `.m3u`, умный `.nsp`,
  выгрузка Яндекса файлом, похоже на Explo, без владельца. Ничего не меняет.
- bodrod 0.17.0:
  - `NavidromeDb.playlists()` — плейлисты из БД Navidrome с владельцем, путём файла, признаком «умный»;
  - `playlist_audit.py` + `GET /api/v1/playlists/audit` (админ) — отчёт выше;
  - выгрузка из Яндекса: `.m3u8` в библиотеку — только при `EXPORT_WRITE_M3U=true` (по умолчанию выключено);
    `GET /api/v1/yandex/export/playlists` — плейлисты выгрузки списком id песен Navidrome. В «Источниках загрузки»
    кнопка «Создать плейлисты Яндекса у меня» создаёт их в учётке нажавшего приватными (существующие по названию
    пропускаются).
- Тесты: `server/tests/test_playlists.py` (4: чтение владельцев, причины отчёта без изменений БД, эндпоинт только
  админу, плейлисты выгрузки → id Navidrome), `test_sources.py` — старый тест m3u с `export_write_m3u=True`;
  `core/subsonic/.../PlaylistOwnershipTest.kt` (2).

## Что нужно сделать на сервере

1. Поставить bodrod 0.17.0 по `docs/DEPLOY.md`: robocopy `server` → «Остановить» → «Создать». Зависимости не менялись.
2. Открыть в приложении «Настройки → Плейлисты на сервере» под администратором. Решить по списку «Проверить
   владельца»: плейлисты из `Плейлисты Яндекса/` — удалить файлы `.m3u8` (тогда Navidrome уберёт плейлисты у админа)
   и нажать «Создать плейлисты Яндекса у меня» под нужной учёткой; плейлисты Explo — проверить `SYSTEM_USERNAME`
   в `/volume1/docker/bodromusic/explo-wife/.env` (должна быть учётка жены, `kalainidi`).
3. Если нужно, чтобы импортированные из файлов плейлисты видели все, — `ND_DEFAULTPLAYLISTPUBLICVISIBILITY: "true"`
   в YAML `bodromusic` (сейчас не задано → приватные у первого админа).
