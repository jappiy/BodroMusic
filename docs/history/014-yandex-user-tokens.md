# 014 — Токены Яндекса по пользователям

- **Дата:** 2026-10-20
- **Версии:** приложение 0.19.0 (`versionCode 20`), bodrod 0.13.0 — общий релиз с заданием 015
- **Релиз с APK:** https://github.com/jappiy/BodroMusic/releases/tag/v0.19.0
- **Образ bodrod:** `ghcr.io/jappiy/bodromusic-server:<хеш коммита 0.19.0>` (см. раздел 1 HANDOFF)
- **Статус:** реализовано; pytest на подделках API Яндекса; на сервере не проверено

## Задание

Баг: экран «Источники загрузки» показывает «Яндекс Музыка — Недоступен: Не задан токен YANDEX_MUSIC_TOKEN», хотя
токен Яндекса задан в секретах bodrod для пользователя jappi.

1. Резолв токена: сначала токен пользователя, от имени которого идёт запрос, затем глобальный `YANDEX_MUSIC_TOKEN`.
   Одна функция, использовать везде.
2. Статус источников — для текущего пользователя приложения; в тексте — откуда токен («токен пользователя» /
   «общий токен»).
3. Загрузки — токеном того, кто поставил заявку; фоновые джобы (чарты, followed artists, wanted labels) — токеном
   владельца задачи, иначе глобальным.
4. Сбор данных Яндекса (лайки, история) — строго токеном пользователя, без fallback на чужой.
5. Различать «не задан» и «невалиден/истёк» (проверка запросом к API при старте и раз в N часов, кэш).
6. Логировать при старте, для каких пользователей найден токен (без самого токена).

Клиент: если пришёл источник токена — подпись под «Яндекс Музыка».

## Что выяснено

- Токены пользователей (`/secrets/yandex_accounts/<пользователь>`, `YANDEX_ACCOUNTS`) читались только для архива
  рекомендаций (`reco/harvest.py`). Источник «Яндекс Музыка» в цепочке загрузок (`sources/yandex.py`) создавался с
  одним API на `YANDEX_MUSIC_TOKEN` — на сервере он не задан, отсюда «Не задан токен».
- Попутно: `YandexMusicApi` не имел метода чарта (тело было по ошибке в `Protocol`) — чарт Яндекса всегда падал
  с `AttributeError` и был скрыт. Исправлено (`chart_tracks`).

## Что сделано

Сервер:
- `bodrod/sources/yandex_tokens.py` (новый) — `YandexTokens`: `resolve(user, fallback=True)` → `TokenRef`
  (токен, `user`/`global`, владелец); заявки пула `pool:<user>` → владелец пула (`request_owner`); API кэшируется по
  токену (у каждого аккаунта своя пауза между запросами); `check()` — статус аккаунта и Плюс запросом к API, кэш на
  `YANDEX_CHECK_INTERVAL_S`, после сетевой ошибки — через 10 минут; состояния `ok` / `no_plus` / `invalid` (401,
  `UnauthorizedError`) / `error`; `check_all()` — все токены (фоновая проверка раз в час); `log_startup()`.
- `sources/yandex.py` — `YandexSource` работает через `YandexTokens`: `status(user)` (причины: «Не задан токен: ни у
  пользователя X, ни общий YANDEX_MUSIC_TOKEN», «Токен недействителен или истёк (токен пользователя)», «Нет подписки
  Плюс (общий токен)», «Не удалось проверить токен (…): …»), `fetch(job)` — API владельца заявки (`FetchJob.owner`),
  `api_for(user)`; `YandexMusicApi.chart_tracks()`.
- `sources/base.py` — `SourceStatus.token_source`, `FetchJob.owner`, `DirectSource.status(user)`.
- `sources/registry.py` — `status/usable/describe(user)`; `SourceOut.tokenSource` + `tokenSourceTitle`.
- `worker.py` — статус источника и загрузка — от имени владельца заявки (`request_owner`).
- `sources/wanted.py` — «метки» Lidarr от имени `lidarr` (нет своего токена → общий). Чарты — `pool:charts` → общий.
- `sources/export.py` — выгрузка запоминает, кто её запустил (`owner` в состоянии), и идёт его токеном, иначе общим.
- `main.py` — `YandexTokens` из `settings.yandex_accounts` + `settings.yandex_token`, лог при старте; `/api/v1/info`,
  `POST /api/v1/requests` — доступность источников для этого пользователя; `/api/v1/sources*` — статус для админа,
  который смотрит; «Проверить подписку» — его токен; харвестер берёт только свои токены
  (`resolve(u, fallback=False)`); метаданные Яндекса — общий токен (как раньше).
- Тесты: `tests/test_yandex_tokens.py` (7): резолв и строгий режим, статус по токену пользователя без общего,
  «недействителен» ≠ «не задан», кэш и повтор после ошибки, загрузка токеном владельца заявки, лог без токенов.

Приложение:
- `core/downloads/Models.kt` — `DownloadSource.tokenSource`, `tokenSourceTitle`.
- `ui/screens/settings/SourcesScreen.kt` — подпись «Токен пользователя» / «Общий токен» под названием источника.

## Решения (агента, владелец может поменять)

- Выгрузка из Яндекса считается фоновой загрузкой, а не «сбором данных»: токен запустившего, иначе общий.
- Время проверки токена — в `details` («Проверен 20.10 12:00»), чей токен — в причине недоступности и в подписи.

## Что нужно сделать на сервере

Образ bodrod 0.13.0 (см. задание 015). Ничего в YAML менять не нужно: токен `jappi` уже лежит в
`/secrets/yandex_accounts/jappi`. В логе при старте должна появиться строка
`Яндекс Музыка: токены пользователей — jappi…; общий токен YANDEX_MUSIC_TOKEN — не задан`, затем результат проверки.
