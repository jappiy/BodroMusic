# 015 — Чарты: скачанные треки не становятся доступными

- **Дата:** 2026-10-20
- **Версии:** приложение 0.19.0 (`versionCode 20`), bodrod 0.13.0 — общий релиз с заданием 014
- **Релиз с APK:** https://github.com/jappiy/BodroMusic/releases/tag/v0.19.0
- **Образ bodrod:** `ghcr.io/jappiy/bodromusic-server:d25e9bf` (CI зелёный на `d25e9bf`)
- **Статус:** реализовано; pytest на подделках; на реальном сервере не проверено

## Задание

После скачивания трек есть в Navidrome (альбом виден в «Альбомах»), но в чарте Deezer остаётся недоступным
(пример: ADÉLA — Nicole Kidman, альбом PRIMA).

1. Прямая привязка при скачивании: `deezer_track_id (+ ISRC) → путь файла`; после скана — song id по пути; для таких
   треков доступность — из привязки, а не из поиска по строкам.
2. Доступность пересчитывать при каждой отдаче чарта (или по событиям), позиции без song id проверять заново.
3. Нормализация: NFKC → casefold → без диакритики; из названия убрать `(with …)`, `(feat. …)`, `[…]`, `- Remaster…`,
   `(Radio Edit)`; артистов разбивать по `, & feat. ft. x with`, совпадение — если основной артист есть в списке;
   запасной путь по ISRC.
4. Клиент: без устаревшего кэша, свежая доступность при открытии; кнопка скачивания → «в очереди / готово» по
   статусу задачи bodrod.
5. Разово пересчитать уже собранные чарты.

## Что выяснено

- Доступность считалась ключом `track_key` по индексу библиотеки, который перестраивался раз в час; ключ не убирал
  диакритику (`adéla` ≠ `adela`) и брал только первого исполнителя трека.
- Кнопка «Скачать» в чарте создавала обычную заявку без связи с позицией; заявка завершалась по поиску Subsonic
  (`search3` по строкам) — при других тегах файла трек «не находился», `songId` у заявки не появлялся.

## Что сделано

Сервер:
- `reco/charts.py` — таблица `chart_links` (`ref` = `<источник>:<id трека>` или `key:<ключ>`, ISRC, заявка, путь,
  id песни); в `chart_entries` новые колонки `ext_id`, `isrc` (Deezer `id`/`isrc`, Яндекс id, Apple id, MBID
  Last.fm и ListenBrainz). `link_request` — при заявке с `chartId`/`chartPosition` и при постановке топа в пул
  «charts»; `resolve_links` — у завершённой заявки id песни по пути файла (БД Navidrome), иначе `songId` заявки;
  `entries` — доступность при каждом запросе: привязка → ключ (любой исполнитель из списка) → ISRC; индекс
  библиотеки перечитывается, если есть недоступные позиции и ему больше 5 минут; в позиции — `requestId`,
  `requestStatus`, новое состояние `queued`. `relink` — разово при старте (`charts.relinked`) и по
  `POST /api/v1/charts/refresh`: завершённые заявки привязываются к позициям собранных чартов по ключу.
  Ключи сохранённых позиций пересчитываются при смене правил (`charts.keys_version`).
- `reco/keys.py` — `fold` (NFKC → casefold → без диакритики у латиницы, кириллица не меняется), хвосты
  `radio version/mix`, `single edit`; `artist_keys`, `track_keys` — ключ для каждого исполнителя; `KEYS_VERSION`.
  `reco/store.py` — пересчёт ключей пула и личных блокировок при смене версии.
- `text.py` — `ARTIST_SPLIT` (публичный) делит и по `with`.
- `reco/library.py` — `LibrarySnapshot.find(artist, title, isrc)`, `library_alt`, `library_isrc`, `ids`;
  `LibraryIndex.age()`, `song_by_path()` (путь bodrod → путь Navidrome).
- `navidrome_db.py` — `song_ids_by_paths` (запрос по пути, с учётом относительных путей Navidrome 0.55+), ISRC из
  колонки `tags`.
- `worker.py` — `song_by_path` (трек находится по пути файла до поиска по строкам), `on_finish` (сброс индекса
  библиотеки после любой заявки); `_finish` больше не статический.
- `models.py` — `CreateRequest.chartId/chartPosition`, `ChartEntryOut.requestId/requestStatus`.
- Тесты: `tests/test_charts.py` (+3: нормализация, привязка по пути и статус заявки, разовый пересчёт),
  `tests/test_navidrome_paths.py` (путь → песня, ISRC, второй исполнитель).

Приложение:
- `core/downloads` — `downloadTrack(track, chartId, chartPosition)`, `ChartEntry.requestId/requestStatus`,
  `isPending`, `isReady`; тест `DownloadsClientTest`.
- `data/reco/ChartsRepository.download(chartId, entry)` — заявка привязана к позиции.
- `ui/screens/charts/ChartScreens.kt` — свежая доступность при открытии и при возвращении на экран
  (`LifecycleResumeEffect`), пока что-то в очереди или качается — обновление раз в 10 с; значки «В очереди»,
  «Качается», «Готово, появится после сканирования».

## Что нужно сделать на сервере

Образ bodrod 0.13.0. При первом старте bodrod сам пересчитает ключи и привяжет уже скачанные треки к чартам
(в логе — «Чарты: пересчёт доступности — привязано заявок N, найдено песен M»). Для поиска по пути и ISRC нужен
`NAVIDROME_DB` (уже задан).

## Что осталось / проверить

- Чарт Deezer: ADÉLA — Nicole Kidman доступна; новый трек, скачанный из чарта, становится доступным после скана.
- ISRC берётся только из Navidrome 0.55+ (колонка `tags`); на старом Navidrome — только привязка и ключи.
