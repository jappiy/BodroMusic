# 045 — «Похожие треки»: в библиотеке и нет в библиотеке

- **Дата:** 2026-10-26
- **Версии:** приложение 0.31.0 (`versionCode 32`), bodrod 0.26.0
- **Релиз с APK:** https://github.com/jappiy/BodroMusic/releases/tag/v0.31.0
- **Статус:** реализовано; сборка и unit-тесты; на телефоне не проверено

## Задание

Разделить «Похожие треки» на «в библиотеке» (без подписи «В библиотеке») и «нет в библиотеке» (кнопка «Скачать»,
статус: в очереди / качается / не найдено / ошибка с повтором, «Скачать все» в шапке). Скачанный трек переезжает в
первую секцию без перезапуска экрана. Обложки треков не из библиотеки — Deezer / Last.fm. Пустую секцию не показывать.

## Что выяснено

- Кнопка скачивания в общей строке `DiscoverTrackRow` была (иконка), но пряталась, если проверка `/info` не удалась:
  `canDownload` становился `false` при любом сбое сети. Обложек не было: Last.fm в похожих картинки не отдаёт.

## Что сделано

- `PlayerExtras.kt`: `similarSections` — две секции. «В библиотеке» — трек с `librarySongId` или с завершённой
  заявкой (`playableId`), строка с `showLibraryMark = false`. «Нет в библиотеке» — `MissingTrackRow`: обложка,
  «Скачать», статус заявки; «не найдено» (`DownloadRequest.isNotFound` — сообщение «Не нашли…») или ошибка —
  «Повторить». Заявки опрашиваются, пока открыт плеер, — трек переезжает сам. «Скачать все» — одной пачкой
  (`POST /api/v1/requests/batch`, на старом сервере — по одной). Сбой `/info` больше не прячет «Скачать».
- bodrod: `metadata/images.py` (`ImageLookup`: Deezer → Last.fm, без заглушек, кэш на сутки); `SimilarTracks`
  подставляет обложки трекам не из библиотеки; `GET /api/v1/images/track`, `GET /api/v1/images/artist`.
- Тесты: `server/tests/test_images.py`, `test_api.py::test_batch_requests_skip_active_and_blank`.
