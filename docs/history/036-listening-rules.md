# 036 — Правило засчитывания прослушиваний и «пропуски по настроению»

- **Дата:** 2026-10-26
- **Версии:** приложение 0.30.0 (`versionCode 31`), Room v3
- **Релиз с APK:** https://github.com/jappiy/BodroMusic/releases/tag/v0.30.0
- **Статус:** реализовано; unit-тесты (`ListenRulesTest`, `WaveSkipRulesTest`, `TrackWavePlannerTest`); на телефоне не проверено

## Задание

Пул задач 2026-10-26, п. 2: описать текущую логику (внутренняя статистика, рекомендации и волна, скробблинг), затем
разделить: скроббл — по стандарту Last.fm/ListenBrainz; внутренние сигналы — ранний пропуск (< 30 с или < ~20 %) слабый
негатив, частичное (~20–50 %) нейтрально, полное (≥ 50 %) позитив, «Не нравится» — жёсткое исключение; кулдаун
пропущенного трека N дней (по умолчанию ~7), понижать вес только при повторных пропусках (3 ранних без полного);
пропуск в волне и в своём плейлисте весят по-разному; по аккаунтам; задокументировать.

## Что выяснено (как было)

- **Скроббл** (Navidrome → Last.fm/ListenBrainz, он же `playCount` для «Коллекции»): трек > 30 с, прослушано
  ≥ min(50 %, 4 мин) реального времени — уже по стандарту, частичные наружу не уходили. Не менялось.
- **Локальная история** (Room `play_history`, по `accountId`): каждое проигрывание ≥ 3 с или с ранним пропуском;
  «ранний пропуск» = пользователь переключил в первые 30 с.
- **Волна (`WaveProfileBuilder` → `WaveEngine`)**: любое непропущенное проигрывание поднимало исполнителя и жанр
  и ставило трек на 7-дневный кулдаун; ранний пропуск самого трека не охлаждал (трек мог прийти в следующей порции),
  но навсегда (до «Сбросить статистику пропусков») понижал исполнителя и жанр — одинаково в волне и в своём плейлисте.
- **Серверная волна bodrod**: события сессии `skip` (ранний пропуск) и `complete` (любое другое проигрывание).
- **Пул «На пробу»**: ≥ 80 % — `completed`, иначе `skipped`.

## Что сделано

- Правило целиком — [`docs/reco/listening-rules.md`](../reco/listening-rules.md).
- `core/domain/.../scrobble/ListenRules.kt` (новый): `PlayOutcome` (EarlySkip / Partial / Full), `PlayContext`
  (Wave 1,0 / Own 0,1 / Other 0,5). `ScrobbleTracker.finish` считает `PlaySession.outcome`.
- `WaveProfile`: `artistSkips`/`genreSkips` — взвешенные (Double), `lastSkippedAt`, `songEarlySkips`,
  `skipCooldownMs`; `WaveProfileBuilder` — полное = позитив, частичное = только «играл недавно», ранний пропуск —
  кулдаун (кроме своих плейлистов), повторные пропуски без полного прослушивания → ×0,3.
- `WaveEngine.isAllowed` — кулдаун пропуска; `adjustedWeight` — штраф за повторные пропуски.
- Room v3 (`AutoMigration 2 → 3`): `play_history.durationMs`, `outcome`, `context`; схема `app/schemas/.../3.json`.
- `PlaybackCoordinator`: контекст по источнику очереди, события пула — только полное и ранний пропуск.
- `WaveRepository.sessionEvents`: `complete` — только полное, частичное серверу не сообщается.
- Настройка «Пропущенный трек в волне»: 1 / 3 / 7 / 14 / 30 дней (`AppSettings.waveSkipCooldownDays`, по умолчанию 7).

  только текущей сессии; при желании перенести туда тот же кулдаун.
