# 024 — Полноэкранный плеер со скроллом (этап 5 из 5)

- **Дата:** 2026-10-23
- **Версии:** приложение 0.26.0 (`versionCode 27`), bodrod 0.20.0
- **Релиз с APK:** https://github.com/jappiy/BodroMusic/releases/tag/v0.26.0
- **bodrod:** 0.20.0 по `docs/DEPLOY.md` (только код)
- **Статус:** реализовано; снимок блоков под плеером в Robolectric, pytest; на телефоне не проверено

## Задание

Этап 5 большого задания (020–024). Верх плеера как у Яндекса: «свернуть» ˅, источник по центру, справа очередь;
основной блок как был. Ниже (прокрутка): карточка исполнителя (фото, имя, ♡ «В избранное» — звезда в Navidrome и
подписка на новые релизы, тап — экран исполнителя); «Похожие треки» (Last.fm `track.getSimilar` + признаки
анализатора; из библиотеки играют сразу, отсутствующие — «Скачать»; меню ⋮: играть следом, в очередь, в плейлист,
волна по треку, скачать); «Популярные треки исполнителя» с той же пометкой; «Скачать все недостающие» для похожих
и для популярных (очередь bodrod с порядком источников из настроек, статусы, скачанный трек играет без перезапуска);
«Добавить в плейлист» — только свои, у каждого +, переход ко всем; внизу — таймер сна и настройки звука. Когда
основной блок уходит за экран, внизу мини-плеер (обложка, название, ♡, пауза). В ландшафте и на разложенном экране —
плеер слева, прокручиваемый список справа.

## Что сделано

- Плеер (`ui/screens/player/FullPlayerScreen.kt`): в портрете — `LazyColumn`, первый элемент — основной блок на
  высоту экрана, ниже блоки; в двух колонках (правило этапа 2) справа — `LazyColumn` с управлением и блоками.
  Шапка: ˅, источник, очередь, ⋮ (таймер сна, волна по треку, действия с треком). Свайп вниз «свернуть» — тот же
  nested scroll, что в этапе 2: срабатывает только у верха списка. Мини-плеер (`PlayerMiniBar`) появляется, когда
  основной блок прокручен за экран.
- Блоки (`ui/screens/player/PlayerExtras.kt`, `PlayerExtrasViewModel`), для каждого нового трека заново:
  - карточка исполнителя: фото, имя, ♡ — `star` исполнителя в Navidrome для текущей учётки. Отдельных подписок на
    исполнителей в bodrod нет; новые релизы по звезде отслеживает `liked2lidarr` (Lidarr, `MONITOR_NEW_ITEMS=all`) —
    сейчас у него `DRY_RUN=true`, т. е. подписка не срабатывает, пока владелец его не выключит;
  - «Похожие треки» — `GET /api/v1/tracks/similar` (bodrod 0.20.0, `metadata/similar.py`): Last.fm
    `track.getSimilar` с пометкой «есть в библиотеке» + до 10 похожих по звучанию из библиотеки (эмбеддинги
    анализатора), без повторов, кэш 6 ч;
  - «Популярные треки исполнителя» — уже существующий `/api/v1/artists/popular` (Яндекс → Deezer → Last.fm);
  - строки — `DiscoverTrackRow` из глобального поиска: есть в библиотеке — играет сразу, нет — «Скачать», статус
    заявки (в очереди / качается / готово / не найдено) из `DownloadsRepository.requests` с опросом, готовый трек
    становится воспроизводимым на месте; у треков из библиотеки — ⋮ (общее меню трека: играть следом, в очередь,
    в плейлист, волна по треку);
  - «Скачать все (N)» у похожих и у популярных — заявки на всё, чего нет и что не качается; порядок источников —
    из «Источников загрузки» (Яндекс → slskd → YouTube → Lidarr);
  - «Добавить в плейлист»: свои плейлисты (до 5) с +, «Все плейлисты и новый плейлист» — общий выбор;
  - внизу: таймер сна (тот же диалог) и качество звука (Оригинал / Медленный интернет).
- Нет сети, bodrod или Last.fm — соответствующие блоки пустые и не показываются.
- Тест: снимок блоков `player-extras` в `WaveHomeScreenshotTest`; `server/tests/test_similar.py` (2).

## Что нужно сделать на сервере

bodrod 0.20.0 по `docs/DEPLOY.md`. Для «Похожих» нужен `LASTFM_API_KEY`; для подписки на новые релизы по ♡ —
выключить `DRY_RUN` у `liked2lidarr` (решение владельца).

  скачанного без перезапуска, ландшафт и разложенный экран.
