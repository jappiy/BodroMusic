# 038 — «Волна по треку»: сразу играет, «следующий» работает, без случайных треков

- **Дата:** 2026-10-26
- **Версии:** приложение 0.30.0 (`versionCode 31`)
- **Релиз с APK:** https://github.com/jappiy/BodroMusic/releases/tag/v0.30.0
- **Статус:** реализовано; unit-тесты `TrackWavePlannerTest`; на телефоне не проверено

## Задание

Пул задач 2026-10-26, п. 4 (приоритет): после запуска «Волны по треку» «следующий» долго не работает или не работает
вовсе; играют будто случайные треки. Диагностировать очередь, задержку, тихий fallback на случайные; семя — сразу,
первая порция (5–10) — быстро из локальных источников, внешние (Last.fm, Deezer) — асинхронно; «следующий» работает
всегда (загрузка и переключение, когда трек появится); без молчаливых случайных треков — честное расширение круга
с логом; в журнал — источник и скор каждого трека; проверить «Похожие по звучанию».

## Что выяснено — причины

1. **Семя не играло сразу.** «Волна по треку» из меню (`MainViewModel.startWave`) ждала всю порцию
   (`WaveRepository.nextBatch`) и только потом запускала очередь — без семени: оно отфильтровывалось
   (`it.id != from.id`). Причём `from` был *текущий* играющий трек, а не трек из меню: подбор смешивал два трека.
2. **Долгий подбор.** Волна по треку шла через общий `LocalWaveSource`: лайки, «часто слушаемое» (6 альбомов),
   3 случайных любимых исполнителя, 3 жанра, похожие исполнители (Last.fm через Navidrome), 2 запроса случайных
   треков, новинки, плюс похожие по звучанию и признаки. Десятки запросов, всё последовательно ждалось, под общим
   замком (`mutex`) — пока сервис подгружал «Мою волну», волна по треку ждала его.
3. **«Случайные треки» — не fallback, а доли «Моей волны».** Для семени-трека доли были: лайки ~12 %, «часто
   слушаемое» ~10 %, открытия (`getRandomSongs`) ~11 %, а в «соседях» — любимые исполнители профиля, не связанные с
   треком; добор недостающего — из любых корзин. Отсюда ощущение случайности.
4. **«Следующий» был выключен.** Кнопки «следующий» в плеере и мини-плеере — `enabled = state.hasNext`: пока порция
   не встала, кнопка неактивна. `continueWithWave` при идущей загрузке молча выходил (`if (waveLoading) return`).
5. **«Похожие по звучанию»** — та же беда: очередь запускалась после загрузки всех похожих (`getSong` по каждому).

## Что сделано

- `core/domain/.../wave/TrackWave.kt` (новый): `TrackWavePlanner` — только похожее на семя: источники `Sound`
  (анализ bodrod), `LastFm` (через bodrod `/tracks/similar`, только из библиотеки), `SimilarArtists` (Navidrome
  `getSimilarSongs2`), `SameArtist` (не больше 30 % порции и не 3 подряд), `Genre` — только если похожих меньше
  порции (флаг `expanded`). Дизлайки — никогда; кулдауны — с ослаблением, если похожих меньше 5 (флаг).
  Скор = место в выдаче источника × вес источника × штраф за повторные пропуски; порядок — по скору с разбросом ±15 %.
- `WaveRepository.trackBatch`: отдельный путь без общего замка. Быстрые источники (звук, исполнитель) — параллельно,
  не дольше 4 с каждый; внешние — один фоновый запуск на семя в `AppScope` (12 с), первая порция ждёт их не дольше
  1,5 с, следующие берут всё. Мало похожих — добор жанром семени и запись «расширение круга». В журнал (`Wave`) —
  итог порции (сколько из какого источника, время, заметки) и в деталях список «исполнитель — трек · источник · скор».
- `PlayerConnection.startTrackWave`: семя играет сразу (`play([семя], WaveSource(byTrack))`), порцию добавляет сервис
  (`checkWaveRefill`); если семя уже играет — хвост очереди меняется без прерывания. `AppActions.startTrackWave`
  (меню трека, меню плеера); `startWave` с семенем-треком находит сам трек (очередь или `getSong`).
- «Следующий» (`PlayerConnection.next`): есть следующий — переключить; волна без следующего — `skipPending`
  (индикатор на кнопке), переключение, как только трек встанет (`onTimelineChanged`), через 20 с — сообщение;
  не волна — продолжить волной от трека. Кнопки в плеере и мини-плеере всегда активны.
- «Похожие по звучанию» — `WaveSettings(soundOnly = true)`: та же схема, только источник `Sound`; заголовок
  «Похоже на «…»».
