# 044 — Перенос лайков из Яндекс Музыки

- **Дата:** 2026-10-26
- **Версии:** приложение 0.31.0 (`versionCode 32`), bodrod 0.26.0
- **Релиз с APK:** https://github.com/jappiy/BodroMusic/releases/tag/v0.31.0
- **Образ bodrod:** `bodrod:local`, собирается на NAS из папки (docs/DEPLOY.md)
- **Статус:** реализовано; pytest на подделках; с настоящим Яндексом и на телефоне не проверено. Приоритет — до 20.11.2026.

## Задание

«Источники музыки» → «Перенести лайки из Яндекс Музыки» отдельно для каждого пользователя: его токен Яндекса, лайки
от его учётки Navidrome. Сопоставление по Yandex ID, затем по нормализованным исполнителю и названию с допуском ±3 с
(feat., ремастеры, ё/е, регистр). Уже стоящие — пропустить, ничего не снимать, «Не нравится» — конфликт. Ненайденные —
«Скачать все ненайденные», после скачивания лайк ставится сам. Идемпотентно, прогресс, отчёт, дата последнего
запуска. Тяжёлая часть — в bodrod.

## Что сделано

- Сервер, `server/bodrod/likes_import.py` (`LikesImport`, `LibraryMatcher`):
  - лайки — `YandexTokens.resolve(user, fallback=False)`: только токен самого пользователя (общий не подставляется);
    нет токена или он недействителен — понятная ошибка в статусе;
  - сопоставление: `library_files.source_id` (id трека Яндекса у скачанных bodrod файлов, `Store.source_paths`)
    → путь → песня Navidrome; затем ключи `reco/keys.track_keys` (каждый исполнитель из списка; без скобок, feat.,
    remaster, «ё», регистра; в одном алфавите) с длительностью ±3 с; резерв (`_reserve`) не считается библиотекой;
  - лайки и «Не нравится» (оценка 1) пользователя — из БД Navidrome (`user_annotations`); лайк — Subsonic `star`
    пачками по 50 **от имени пользователя**, теми же учётными данными (token + salt), с которыми приложение пришло
    в bodrod. Они держатся только в памяти (`remember` в `current_user`) — для отложенных лайков после докачки;
  - ненайденные → `POST /yandex/likes/download` создаёт обычные заявки (цепочка источников); раз в минуту и при каждом
    опросе статуса `settle` ставит лайк докачанным (попавшие в «Не нравится» уходят в конфликты);
  - состояние — kv `likes_import.<user>`: прогресс, отчёт, конфликты, ненайденные с заявками, `lastRunAt`; повторный
    запуск считает всё заново, ничего не снимает, ссылки на заявки сохраняются;
  - API: `GET /api/v1/yandex/likes`, `POST /api/v1/yandex/likes/run`, `POST /api/v1/yandex/likes/download`
    (`{"ids": [...]}` или все); в `/info` — `likesImport`.
- Приложение: `ui/screens/settings/LikesImportScreen.kt` (экран; опрос 1,5 с во время переноса, 5 с — пока качаются
  ненайденные); вход — первая строка «Источников загрузки», виден и не-администраторам (при 403 цепочки источников
  экран показывает вход и ошибку под ним); `DownloadsClient.likesImport / runLikesImport / downloadLikesMissing`.
- Тесты: `server/tests/test_likes_import.py` (6) — правила сопоставления, отчёт, идемпотентность, докачка → лайк,
  конфликт после докачки, нет токена.

## Что осталось / проверить

- Поставить bodrod 0.26.0 на NAS («Остановить» → «Создать»), под каждым пользователем запустить перенос до 20.11.
- Проверить отчёт на реальной библиотеке: долю «не найдено» и нет ли ложных совпадений (разные версии одной длины).
- После перезапуска bodrod отложенные лайки ставятся, когда пользователь снова откроет приложение (учётные данные
  только в памяти).
