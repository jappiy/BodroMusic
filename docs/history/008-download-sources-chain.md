# 008 — Цепочка источников загрузки, Яндекс Музыка и YouTube Music

- **Дата:** 2026-10-19
- **Версии:** приложение 0.14.0 (`versionCode 15`), bodrod 0.7.0
- **Релиз с APK:** https://github.com/jappiy/BodroMusic/releases/tag/v0.14.0
- **Образ bodrod:** `ghcr.io/jappiy/bodromusic-server:9fc4188`
- **Статус:** реализовано; CI зелёный на `9fc4188` (Android с эмулятором, сервер — 113 тестов pytest и ruff); адаптеры Яндекса (поиск, альбом, дискография)
  и YouTube Music (поиск, альбом, настоящая загрузка yt-dlp) проверены против настоящих API с компьютера владельца;
  **скачивание из Яндекса (FLAC/encraw) не проверялось** — нужен токен аккаунта с Плюсом; на сервере не запускалось

## Задание

Сейчас bodrod ищет треки в slskd, а альбомы и артисты идут через Lidarr. Нужна единая настраиваемая цепочка
источников и два новых: Яндекс Музыка (API, FLAC) и YouTube Music (ytmusicapi + yt-dlp). Порядок по умолчанию:
Яндекс → slskd → YouTube Music → Lidarr. Цепочка одинаково работает для трека, альбома, добавления артиста в
отслеживаемые и загрузки по меткам; для каждой позиции — источники сверху вниз до первого успешного.

Подробно (сокращённо по пунктам владельца):
1. Общий интерфейс источника; порядок и флаг enabled в конфиге bodrod; отключённый/недоступный — пропуск с записью
   в лог; история попыток по каждому запросу; итоговый источник («Яндекс, FLAC») — в статусе заявки в приложении.
2. Яндекс: библиотека yandex-music (MarshalX) с `[crypto]` (encraw), токен в секретах; FLAC, иначе AAC 192;
   сопоставление «артист + название» с нормализацией и длительностью ±3 с; защита от превью (< 90 % длительности —
   удалить, неудача); альбомы и артисты — альбом целиком по ID; задержка 2–3 с между запросами; пропуск уже
   имеющегося; проверка Плюса при старте и раз в сутки (нет подписки → «недоступен» с причиной); теги и обложка
   из Яндекса, раскладка как у slskd.
3. Два переключателя: «Яндекс: скачивание» (выключить после конца подписки 20 ноября) и «Яндекс: метаданные»
   (поиск, теги, обложки, тексты; работает на бесплатном аккаунте). При включённых метаданных треки из slskd и
   YouTube перетегируются по Яндексу при уверенном совпадении.
4. YouTube Music: ytmusicapi (только «song»), yt-dlp bestaudio (opus/m4a) без перекодирования; длительность ±3 с,
   клипы/live/cover/remix отбрасывать, если их нет в запросе; прокси для yt-dlp; обновление yt-dlp; пометка lossy.
5. Lidarr — последний источник для альбомов и артистов (Soularr не меняется); туда — только ненайденное выше.
6. Экран «Источники загрузки» (админ): переключатели, порядок перетаскиванием, статус и причина; отдельно
   «Яндекс: метаданные».
7. Массовая выгрузка из Яндекса до 20 ноября: «Мне нравится», все мои плейлисты, полные дискографии выбранных
   артистов (список из лайков с отметкой «брать целиком»); низкий приоритет, задержки, возобновление после
   перезапуска, пропуск имеющегося, прогресс в приложении.

## Решения владельца

- «Загрузка по меткам» — это мониторинг в Lidarr: отслеживаемый артист → Lidarr помечает недостающие альбомы
  (wanted) → их пытаются скачать по всем каналам. Теперь эти альбомы тоже идут через цепочку bodrod.

## Решения по ходу (агент)

- bodrod на Python — yandex-music подключена напрямую, без отдельного сервиса.
- «Яндекс: скачивание» — это переключатель источника `yandex` в цепочке; «недоступен» (нет Плюса, нет токена) —
  отдельное состояние, ручной переключатель при этом не меняется.
- slskd альбомы не качает (это делает Soularr через Lidarr) — в цепочке альбома и исполнителя его нет.
- «Метки»: заявки создаются от служебного пользователя `lidarr` (в приложении не видны), цепочка без Lidarr;
  не найденное остаётся Lidarr/Soularr, повтор цепочкой — через 7 дней.
- Исполнитель, скачанный Яндексом/YouTube, добавляется в Lidarr с `monitor: future` — дальше новые релизы приходят
  «метками» и снова идут через цепочку. Это и есть «добавление в отслеживаемые» без отправки в Lidarr лишнего.
- Повтор при неудаче теперь общий для цепочки (раньше — только для поиска в Soulseek): `SLSKD_RETRY_*`.
- yt-dlp запускается отдельным процессом, обновляется `pip --target <DATA_DIR>/ytdlp` — новая версия действует без
  перезапуска контейнера. В образ добавлен ffmpeg: поток opus/aac перекладывается в `.opus`/`.m4a` без
  перекодирования (в webm теги не записать).
- Плейлисты выгрузки пишутся `.m3u8` в `<LIBRARY_DIR>/Плейлисты Яндекса/` — Navidrome импортирует их сам.
- Создание заявки «альбом» из приложения не добавлено (в API есть, `kind: "album"`): альбомы приходят «метками».

## Что выяснено

- yandex-music 3.2.2: lossless — `tracks_file_info(quality="lossless", codecs=["flac"], transport="encraw")`,
  `download_info.download()` расшифровывает сам (нужен `cryptography`). Подписка — `account_status().plus.has_plus`.
  Без токена поиск, альбомы и дискографии работают (проверено).
- ytmusicapi 1.12: с `language="ru"` поиск возвращает пустой список (не разбирает локализованные категории) —
  используется язык по умолчанию. Обложки приходят 60–120 px — в адресе подменяется размер на 1200.
- yt-dlp без ffmpeg на этом компьютере скачал m4a (284 с) — так же поведёт себя образ без ffmpeg.
- Клиент < 0.14 упал бы на заявке `kind: "album"` в списке, но такие заявки создаёт только «метки» (пользователь
  `lidarr`) — в списках людей их нет.

## Что сделано

- Сервер (bodrod 0.7.0), пакет `server/bodrod/sources/`:
  - `base.py` — `DirectSource`, `SourceStatus`, `SourceMiss`, `FetchJob`/`FetchResult`/`FetchedFile`,
    сопоставление (`track_score`, `unwanted_extras`), защита от превью (`is_preview`);
  - `registry.py` — `SourceRegistry`: порядок, переключатели, «Яндекс: метаданные» (таблица `kv`), статусы, описание
    для API;
  - `yandex.py` — `YandexMusicApi` (yandex-music в потоке, пауза 2–3 с), `YandexSource` (трек, альбом, дискография,
    FLAC → AAC, превью, Плюс раз в сутки), `YandexMetadata` (перетегирование);
  - `youtube.py` — `YtMusicClient`, `YtDlpProcess` (загрузка, версия, обновление), `YouTubeSource`;
  - `placer.py` — раскладка файлов прямых источников, перетегирование, запись в `library_files`;
  - `wanted.py` — `LidarrWantedSync` («метки»); `export.py` — `YandexExport` (массовая выгрузка).
  - `worker.py` переписан на цепочку: `chain`/`chain_index`/`attempts`/`source_label` у заявки, прямые источники —
    фоновые задачи, slskd и Lidarr — прежние шаги; заявки «альбом» (Lidarr: `add_album`, `album_stats`).
  - `db.py`: схема 2 — новые колонки заявок, таблицы `kv`, `library_files`, `wanted_seen`, `export_items`,
    `export_artists`; заявки до 0.7.0 продолжают со своим источником.
  - `placement.py`: теги номер трека, диск, год, жанр, текст; `clients/lidarr.py`: `follow_artist`,
    `refresh_artist`, `add_album`, `wanted_missing`; `metadata/providers.py`: Яндекс-каталог слушается
    переключателя «метаданные».
  - `main.py`: эндпоинты `/api/v1/sources*`, `/api/v1/yandex/export*`, `kind: "album"`, `info` с `albumDownloads`
    и `sources`; фоновые «метки», выгрузка, проверка подписки и обновление yt-dlp.
  - `requirements.txt` (+ yandex-music[crypto], ytmusicapi, yt-dlp), `Dockerfile` (+ ffmpeg), `README.md`,
    `docker-compose.example.yml`.
- Приложение 0.14.0:
  - `core/downloads`: `RequestKind.Album`, `DownloadRequest.source/attempts`, `DownloadSources`, `ExportStatus`,
    `ExportArtist`, методы клиента для источников и выгрузки;
  - `ui/screens/settings/SourcesScreen.kt` — «Источники загрузки» (перетаскивание за ручку, переключатели, статусы,
    «Яндекс: метаданные», «Проверить подписку», «Обновить yt-dlp», карточка выгрузки) и «Артисты целиком»;
  - `DownloadsScreen.kt` — источник и неудачные попытки под заявкой, заявки-альбомы; уведомление «Альбом скачан».
- Тесты: сервер `tests/test_sources.py` (23: цепочка, порядок и переключатели, Яндекс FLAC/AAC/превью/без Плюса/

## Что нужно сделать на сервере

1. Токен Яндекс Музыки аккаунта с Плюсом — в `/volume1/docker/bodrod/secrets/yandex_music_token` (права 600,
   владелец 1027), как `lastfm_api_key`. Получить токен: https://yandex-music.readthedocs.io/en/main/token.html.
2. Обновить образ bodrod до 0.7.0 (тег — см. шапку). В логе при старте: «Цепочка источников: yandex, slskd, youtube,
   lidarr» и «Яндекс Музыка: подписка Плюс есть».
3. По желанию: `YOUTUBE_PROXY` (если YouTube с сервера не открывается — через VPN-контейнер).
4. В приложении (админ): Настройки → Источники загрузки — проверить статусы; Выгрузка из Яндекса → «Выбрать
   артистов» → «Собрать из лайков», отметить, «Начать». После 20 ноября выключить «Яндекс Музыка» в цепочке.
5. `LIDARR_WANTED_SYNC` включён по умолчанию: через минуту после старта bodrod возьмёт до 20 недостающих альбомов.
   Если не нужно — `LIDARR_WANTED_SYNC=false`.
