## 1. Осмысленные подводки к трекам (строка «✦ …» под треком на главной)

**Проблема.** Очень часто показывается шаблон «Трек из альбома «Alien»» — бесполезно, а для синглов (альбом = название трека) выглядит совсем глупо.

**Что сделать.**

Генерация подводок переезжает в bodrod: ночной регламент считает и кэширует текст для каждого трека библиотеки и пула «На пробу», клиент получает готовую строку (плюс контекстную часть, см. ниже).

Источники фактов (бери то, что уже есть в bodrod, недостающее добавь):
- **Причина попадания в волну** (самое ценное для режима «Незнакомое»): «похоже на X, который вы лайкнули», «часто слушают вместе с Y» (Last.fm similar), «новый релиз артиста, на которого вы подписаны», «из чарта Deezer за неделю». Это контекстная часть — считается в момент формирования волны, а не ночью.
- **Личная история**: число прослушиваний, давно не звучал («вы не слушали его с весны»), первое прослушивание артиста, лайкнут женой/другим пользователем общей библиотеки (только факт «в общей библиотеке его любят», без раскрытия чужих подробностей, если так не настроено).
- **Анализ звучания**: темп, энергия, настроение («медленный и тёмный, 72 BPM», «самый энергичный трек альбома»).
- **Last.fm**: теги трека/артиста, краткая выжимка wiki трека или bio артиста (одно предложение, без ссылок и «Read more on Last.fm»), год, слушатели.
- **Релиз**: год, юбилей альбома («альбому сегодня 20 лет»), позиция трека («открывающий трек альбома»), лейбл.

Генератор:
- Набор русскоязычных шаблонов (≥30) по типам фактов, выбор с весами по «интересности» факта.
- Антиповтор: в одной волне один и тот же тип подводки не чаще раза в 5 треков; один и тот же текст для трека не крутить бесконечно — ротация между 2–3 вариантами.
- Длина ≤ 90 символов, одна строка-мысль, без канцелярита.
- Фолбэк «Трек из альбома X» **запрещён**, если альбом совпадает с названием трека или это сингл. В остальных случаях — только если вообще нет ни одного факта.
- Опциональный режим ИИ: настройка bodrod `BLURB_LLM_PROVIDER` = `none` (по умолчанию) | `anthropic` | `ollama`. При включении — генерация живого текста по собранным фактам ночью, один раз на трек, с кэшем; при ошибке — шаблоны. Промпт: только из переданных фактов, ничего не выдумывать.

Хранение: таблица подводок в БД bodrod (track_id, text, facts_hash, generated_at, source). Пересчёт при изменении фактов. Эндпоинт для клиента — по списку track_id.

## 4. Туманность на главной, реагирующая на музыку

**Проблема.** Сейчас фон — размытое пятно, которое очень медленно плавает («как при катаракте»).

**Референс** — `nebula_reference.jpg`: плотный «дымный» фиолетовый слой с тонкими светлыми прожилками-разрядами, заметное течение (за 2 с картинка ощутимо меняется), лёгкая пульсация яркости в ритм, верхние ~45% экрана — туманность, ниже плавное затухание в чёрный под кнопками настроений.

### 4.1 Рендер
AGSL `RuntimeShader` (API 33+) через `ShaderBrush` в Compose. Если `minSdk` < 33 — тот же шейдер на GLES (`TextureView`), на совсем старых — текущий градиент.

Шейдер (прототип, по нему сделан `nebula_prototype.png`; параметры можно доводить):

```glsl
uniform float2 uRes;
uniform float  uTime;      // фаза, интегрируется на CPU (см. 4.3)
uniform float  uEnergy;    // 0..1 громкость, сглаженная
uniform float  uBeat;      // 0..1 импульс на долю, затухает
uniform float3 uColA;      // тёмный цвет
uniform float3 uColB;      // основной
uniform float3 uColC;      // прожилки
uniform float  uFadeStart; // 0.42 — где начинается затухание (доля высоты)
uniform float  uFadeLen;   // 0.33

float hash(float2 p) {
    float3 p3 = fract(float3(p.xyx) * 0.1031);
    p3 += dot(p3, p3.yzx + 33.33);
    return fract((p3.x + p3.y) * p3.z);
}
float vnoise(float2 p) {
    float2 i = floor(p); float2 f = fract(p);
    float2 u = f * f * (3.0 - 2.0 * f);
    float a = hash(i), b = hash(i + float2(1,0)), c = hash(i + float2(0,1)), d = hash(i + float2(1,1));
    return a + (b - a) * u.x + (c - a) * u.y + (a - b - c + d) * u.x * u.y;
}
const float2x2 M = float2x2(1.6, -1.2, 1.2, 1.6);
float fbm4(float2 p) { float v = 0.0, a = 0.5; for (int i = 0; i < 4; i++) { v += a * vnoise(p); p = M * p; a *= 0.5; } return v; }
float fbm5(float2 p) { float v = 0.0, a = 0.5; for (int i = 0; i < 5; i++) { v += a * vnoise(p); p = M * p; a *= 0.5; } return v; }

half4 main(float2 fc) {
    float2 uv = fc / uRes;
    float asp = uRes.x / uRes.y;
    float2 p = float2((uv.x - 0.5) * asp, uv.y - 0.35) * 1.8;
    p *= 1.0 - 0.025 * uBeat;                       // лёгкий «вдох» на долю
    float t = uTime;
    float2 q = float2(fbm4(p + float2(t * 0.05, t * 0.07)),
                      fbm4(p + float2(5.2 - t * 0.06, 1.3 + t * 0.04)));
    float2 r = float2(fbm4(p + 2.5 * q + float2(1.7 + t * 0.11, 9.2)),
                      fbm4(p + 2.5 * q + float2(8.3, 2.8 - t * 0.09)));
    float f = fbm5(p + 2.0 * r);
    float smoke = clamp(0.35 + (f - 0.5) * 1.3, 0.0, 1.0);
    float rid = 1.0 - abs(2.0 * fbm5(p * 1.4 + 2.2 * r + float2(t * 0.03, 0.0)) - 1.0);
    float fil = pow(rid, 14.0 - 5.0 * uEnergy);     // прожилки толще на громком
    float3 col = mix(uColA, uColB, smoke) + uColC * fil * (0.35 + 0.35 * uEnergy + 0.3 * uBeat);
    col *= 0.9 + 0.12 * uEnergy + 0.15 * uBeat;
    col = 1.0 - exp(-col * 1.6);                    // мягкий тонмаппинг, без пересвета
    float fade = pow(clamp(1.0 - (uv.y - uFadeStart) / uFadeLen, 0.0, 1.0), 1.6);
    return half4(half3(col * fade), 1.0);
}
```

Производительность: шейдер мягкий, можно рендерить в слой ½ разрешения и растягивать с билинейной фильтрацией. Цель — ≤ 4 мс GPU на кадр. Рисовать только когда главная видна и приложение на переднем плане; в режиме энергосбережения — 30 fps; при системном «уменьшить движение» — медленный режим без пульсации. В настройках «Внешний вид» — переключатель «Анимированный фон»: Полный / Экономный / Выкл.

### 4.2 Палитра
Берётся из текущей логики цвета главной (обложка/настроение):
`uColB` — доминантный цвет с повышенной насыщенностью (яркость ~0.8), `uColA` ≈ `uColB × 0.45`, `uColC` = `mix(uColB, белый, 0.6)`. Смена трека — плавный переход палитры ~800 мс. Читаемость заголовка артиста и кнопок сохранить (при необходимости — мягкий скрим под текстом).

### 4.3 Реакция на ритм
- **Не использовать** `android.media.audiofx.Visualizer` (требует разрешение на микрофон).
- Снимать PCM прямо из плеера: `TeeAudioProcessor` + свой `AudioBufferSink`, подключённый через `DefaultAudioSink.Builder().setAudioProcessors(...)` в `RenderersFactory`. Если плеер устроен иначе — аналогичный перехват PCM до вывода.
- Анализ на аудиопотоке (не на UI-потоке): моно; полная RMS → энергия; ФНЧ ~150 Гц (biquad) → бас; спектральный поток/рост баса выше адаптивного порога (среднее + 1.5σ за ~1 с), рефрактерность 200 мс → событие доли.
- Сглаживание: энергия — атака ~50 мс, спад ~400 мс; нормировка по скользящему максимуму за ~10 с (AGC), чтобы тихие и громкие треки двигали фон одинаково. `uBeat` = 1 на долю, экспоненциальное затухание τ ≈ 180 мс.
- **Синхронизация с наушниками**: буфер обрабатывается раньше, чем звучит (у Bluetooth задержка 200+ мс). Писать значения в кольцевой буфер с медиавременем (позиция на момент flush + обработанные кадры / sample rate) и в UI брать значение по `player.currentPosition` — тогда задержка вывода учтётся автоматически.
- Если анализатор на сервере даёт BPM/сетку долей — можно использовать как подсказку для порога, но основной источник — живой PCM.
- Скорость течения: фаза `uTime` интегрируется на CPU: `phase += dt * speed`, `speed = 0.8 + 1.2 * energy` при воспроизведении, `0.25` на паузе (плавный переход скорости, без рывков).

## 8. Тексты песен: массовый сбор + перемотка по строкам

### 8.1 Сбор (bodrod)
Источники по приоритету:
1. **Яндекс Музыка — срочно, до 20.11.2026** (подписка Plus активна до этой даты). Разовый массовый проход по всей библиотеке: синхронизированный текст (LRC), если нет — обычный. Сопоставление треков — по сохранённым id Яндекса, иначе поиск по артисту + названию + длительности (±2 с). Использовать тот клиент Яндекс API, что уже есть в bodrod.
2. **LRCLIB** (`lrclib.net`, бесплатно, без ключа): `/api/get` по artist/track/album/duration, при промахе — `/api/search` с проверкой длительности ±2 с. Обязателен свой User-Agent (`BodroMusic/<версия>`), не чаще ~1 запроса/с. Флаг `instrumental` — запоминать как «текста нет и не будет».
3. Обычный текст без таймингов — только если синхронизированного нигде нет.

Хранение:
- Писать `.lrc` (или `.txt` для несинхронизированного) рядом с аудиофайлом, с тем же именем. Существующие тексты (встроенные в теги и файлы) не перезаписывать. После пачки — запрос пересканирования Navidrome.
- Проверь версию Navidrome и его настройку приоритета текстов (`LyricsPriority`): внешние `.lrc`/`.txt` должны подхватываться. Если версия не умеет — вариант Б: bodrod отдаёт тексты своим эндпоинтом, клиент берёт их, когда Navidrome текста не вернул. Файлы аудио не модифицировать.
- В БД bodrod статус по треку: источник, synced/plain/instrumental/not_found, дата попытки.

Регламент:
- Добавить шаг в ежедневный ночной регламент: новые треки без текста + повторы для `not_found` (через 7 дней, затем через 30, затем раз в 90).
- Плюс разовая задача «собрать тексты по всей библиотеке» с запуском из приложения/админки и прогрессом; Яндекс-проход запустить сразу после реализации.
- В ночном отчёте — сколько найдено (synced/plain), сколько не найдено.

### 8.2 Перемотка по строкам (клиент)
- Для синхронизированного текста: тап по строке → `seekTo(startMs строки)`, воспроизведение продолжается (если была пауза — остаётся пауза, позиция меняется).
- Подсветка текущей строки и автоскролл к ней; если пользователь сам листает — автоскролл замирает на ~3 с после последнего касания, затем плавно возвращается к текущей строке.
- Для текста без таймингов строки не кликабельны, показывать обычным текстом.
- Пустые строки LRC (паузы) не ломают подсветку.
