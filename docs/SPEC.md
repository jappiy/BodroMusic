## 0. Роль и контекст

Ты — senior Android-разработчик. Твоя задача — с нуля разработать нативное Android-приложение **BodroMusic** — клиент для прослушивания музыки с домашнего сервера **Navidrome** (Subsonic API + расширения OpenSubsonic).

Контекст инфраструктуры:
- Navidrome крутится в Docker на домашнем сервере (Xpenology / Synology DSM). Есть белый IP и DDNS, то есть сервер доступен и из локальной сети, и снаружи.
- Музыкой пользуются **несколько человек**. Медиатека (треки, альбомы, исполнители) — **общая**. У каждого человека **своя учётная запись Navidrome**, а значит свои: избранное (лайки), рейтинги, плейлисты, история прослушиваний, «волна».
- Рекомендаций Last.fm на сервере **нет** (Last.fm не подключён). Не полагайся на `getSimilarSongs`/`getArtistInfo` как на основной источник — они могут возвращать пустоту. Используй их только как опциональный бонус, если вернулись данные.
- Пользователь сам тестирует руками и даёт обратную связь. Не пиши ему инструкций «как протестировать» — просто делай и отчитывайся, что сделано.

## 1. Цель версии 1.0

Рабочее приложение, которое можно поставить на телефон и пользоваться каждый день:
1. Вход в свою учётку Navidrome, работа в LAN и через интернет.
2. Главный экран, библиотека, поиск, плеер — в визуальном стиле референсов.
3. Стабильное **фоновое** воспроизведение с уведомлением и управлением с экрана блокировки / наушников.
4. Запоминание очереди и позиции между перезапусками.
5. Отправка прослушиваний (scrobble) обратно в Navidrome, включая офлайн-очередь.
6. Лайки и дизлайки; дизлайкнутые треки никогда не попадают в «Мою волну» этого пользователя.
7. «Моя волна» — бесконечный персональный поток (алгоритм в разделе 5).
8. Экран истории версий приложения в настройках.
9. Экран логов обмена с Navidrome в настройках.
10. Автотесты (unit + инструментальные на подключённом телефоне), прогнанные тобой самостоятельно.

**Не входит в 1.0** (не делай, но не закрывай архитектурно): офлайн-скачивание треков для прослушивания без сети, Android Auto, Chromecast, виджет на рабочий стол, эквалайзер, заказ треков с телефона, анализ настроения треков. Это roadmap (раздел 12).

## 2. Технологический стек

Используй актуальные **стабильные** версии библиотек на момент начала работы (проверь, не выдумывай номера версий). Version catalog `gradle/libs.versions.toml`.

- Kotlin, Gradle Kotlin DSL, один модуль `app` (допустимо разбить на `:core:network`, `:core:data`, `:core:player`, `:feature:*`, если сочтёшь нужным — но без оверинжиниринга).
- UI: **Jetpack Compose + Material 3**, Navigation Compose, edge-to-edge.
- Плеер: **AndroidX Media3** — `ExoPlayer`, `MediaSessionService` (лучше сразу `MediaLibraryService`, чтобы позже добавить Android Auto), `media3-datasource-okhttp`, `SimpleCache` для кэша стрима.
- Сеть: OkHttp + Retrofit (или Ktor client) + kotlinx.serialization; Subsonic запросы с `f=json`.
- DI: Hilt.
- Хранилище: Room (локальный кэш метаданных, очередь, дизлайки, очередь скробблов, логи), DataStore (настройки).
- Секреты: пароль хранить зашифрованно (Android Keystore + Tink / аналог). Никогда не писать пароль, token, salt в логи и в Room в открытом виде.
- Изображения: Coil (с дисковым кэшем), извлечение цветов обложки — `androidx.palette`.
- Фоновые задачи: WorkManager (отправка отложенных скробблов).
- Тесты: JUnit, kotlinx-coroutines-test, Turbine, MockK, **OkHttp MockWebServer**, Compose UI Test, Espresso/UiAutomator для инструментальных.
- minSdk 26, targetSdk/compileSdk — последний стабильный.
- applicationId: `ru.bodro.music` (debug: суффикс `.debug`, чтобы стоять рядом с релизом).

Архитектура: MVVM + UDF (ViewModel → `StateFlow<UiState>`), репозитории, слой `data/remote` (Subsonic API) и `data/local` (Room). Источник правды для «социальных» данных пользователя (лайки, рейтинги, плейлисты, история) — **сервер**; Room — кэш + офлайн-очереди изменений.

## 3. Работа с Navidrome (Subsonic / OpenSubsonic API)

### 3.1. Аутентификация
- Параметры каждого запроса: `u`, `t` = md5(password + salt), `s` = случайный salt (новый на каждый запрос), `v=1.16.1`, `c=BodroMusic`, `f=json`.
- При входе: `ping.view`, затем `getOpenSubsonicExtensions.view` (если поддерживается — запомнить список расширений и использовать их, например `songLyrics`).
- Обработка ошибок Subsonic (`status=failed`, коды 10/40/41/50/70) → понятные русские сообщения в UI.

### 3.2. Адреса сервера
- В настройках учётки два адреса: **локальный** (например `http://192.168.x.x:4533`) и **внешний** (DDNS, `https://...`).
- Автовыбор: при старте и при смене сети (ConnectivityManager callback) пробовать локальный с коротким таймаутом, иначе внешний. Текущий активный адрес показывать в настройках и в логах.
- Поддерживать HTTPS с нормальным сертификатом. Self-signed не поддерживать в 1.0. Cleartext HTTP разрешить только для приватных адресов (network security config).

### 3.3. Несколько пользователей
- Каждый человек логинится под своей учёткой Navidrome.
- Поддержать **несколько учёток на одном устройстве** с переключением (экран «Аккаунты» в настройках). Все локальные данные (Room, кэш очереди, дизлайки, логи) разделять по `accountId`. При переключении — остановить воспроизведение, очистить очередь в памяти, подгрузить состояние этой учётки.

### 3.4. Используемые эндпоинты (минимум)
- Библиотека: `getArtists`, `getArtist`, `getAlbum`, `getAlbumList2` (типы `newest`, `recent`, `frequent`, `random`, `starred`, `byGenre`, `byYear`, `alphabeticalByName`), `getSong`, `getGenres`, `getSongsByGenre`, `getRandomSongs` (с `genre`, `fromYear`, `toYear`), `search3`, `getStarred2`.
- Плейлисты: `getPlaylists`, `getPlaylist`, `createPlaylist`, `updatePlaylist`, `deletePlaylist` — только плейлисты текущего пользователя редактируемы; публичные чужие — только чтение.
- Медиа: `stream` (параметры `maxBitRate`, `format`), `getCoverArt` (с `size`), `getLyricsBySongId` (OpenSubsonic) с fallback на `getLyrics`.
- Действия: `star`/`unstar`, `setRating`, `scrobble`.
- Опционально: `getSimilarSongs2`, `getTopSongs` — использовать только если вернули непустой результат.

### 3.5. Скробблинг (история прослушиваний)
- При старте трека: `scrobble?id=…&submission=false` (now playing).
- Засчитать прослушивание, когда проиграно **≥ 50% длительности или ≥ 4 минут** (что раньше), трек длиннее 30 с: `scrobble?id=…&time=<unix ms начала>&submission=true`.
- Если сети нет / ошибка — положить в Room-очередь `pending_scrobbles` (accountId, songId, timestamp) и отправить через WorkManager при появлении сети, в хронологическом порядке, с ретраями. Не терять и не дублировать.
- Локально тоже вести историю прослушиваний (для «Недавно прослушанного» и алгоритма волны).

### 3.6. Лайки и дизлайки
- **Лайк** = `star` трека (и снятие — `unstar`). Также лайк альбома и исполнителя (star с `albumId`/`artistId`).
- **Дизлайк**: в Subsonic API нет дизлайка. Реализация:
  - на сервер: `setRating(id, rating=1)` — соглашение «рейтинг 1 = дизлайк»; снятие дизлайка → `setRating(id, 0)`;
  - локально: таблица `disliked_tracks(accountId, songId, createdAt, syncState)`;
  - при синхронизации считать дизлайкнутыми все треки пользователя с `userRating == 1` (подтягивать при открытии/обновлении данных).
- Лайк и дизлайк взаимоисключающие: поставил дизлайк → снять star; поставил лайк → снять рейтинг 1.
- Дизлайк во время воспроизведения в волне → **сразу** перейти к следующему треку и вычистить трек из оставшейся очереди волны.
- Дизлайкнутые треки: исключаются из «Моей волны», миксов и любых автогенерируемых подборок. В альбоме/поиске/плейлистах остаются видимыми (с иконкой), но не удаляются — пользователь может сознательно включить.
- Все изменения — оптимистично в UI + очередь синхронизации при отсутствии сети.

## 4. Воспроизведение

- `MediaLibraryService` + `MediaSession`, foreground-уведомление со стандартными контролами (prev/play-pause/next) + кастомная кнопка «лайк».
- Работа с экрана блокировки, Bluetooth-гарнитуры, кнопок наушников.
- Audio focus (приглушение при уведомлениях, пауза при звонке), пауза при отключении наушников (`ACTION_AUDIO_BECOMING_NOISY`).
- Gapless там, где поддерживается; предзагрузка следующего трека.
- Режимы: повтор (выкл / вся очередь / один трек), перемешивание.
- Очередь: просмотр, перетаскивание, удаление, «играть следующим», «в конец очереди».
- Таймер сна (15/30/45/60 мин / до конца трека).
- Качество: настройки «Wi-Fi» и «Мобильная сеть» отдельно: «Оригинал (без потерь)» / 320 / 192 / 128 kbps (через `maxBitRate`, `format=mp3` или `opus` при транскодировании). На плеере показывать бейдж качества («Без потерь», «FLAC 16/44», «MP3 320» — по `suffix`/`bitRate` трека), как на референсе Symfonium.
- Кэш стрима (SimpleCache, LRU, размер настраивается, по умолчанию 1 ГБ) — повторное прослушивание без трафика.
- **Восстановление состояния**: при каждом изменении очереди/трека и раз в ~5 с во время воспроизведения сохранять в Room: очередь (id треков), индекс, позицию, режимы повтора/шаффла, источник очереди (альбом/плейлист/волна). После перезапуска приложения/телефона — мини-плеер показывает последний трек на сохранённой позиции, play продолжает с того же места. Если источник — волна, продолжить волну.
- Не убивать процесс без нужды; корректно обрабатывать ограничения фона Android 12+ (foreground service type `mediaPlayback`).

## 5. «Моя волна» (алгоритм рекомендаций v1, на клиенте)

Сервер не даёт рекомендаций, поэтому волна строится на клиенте из данных **текущего пользователя**. Алгоритм вынести в отдельный класс `WaveEngine` с интерфейсом `WaveSource`, чтобы позже можно было подключить серверный источник (ListenBrainz и т.п.) без переделки UI.

Генерация порциями по 20 треков, следующая порция подгружается, когда в очереди остаётся ≤ 5 треков. Пул кандидатов:
1. Лайкнутые треки пользователя (`getStarred2`) — ~25%.
2. Часто и недавно слушаемое: треки из альбомов `frequent` и `recent` — ~20%.
3. «Соседи по вкусу»: другие треки тех исполнителей и жанров, которые пользователь лайкал / часто слушал (`getArtist`, `getSongsByGenre`) — ~35%.
4. «Открытия»: `getRandomSongs` с фильтром по любимым жанрам + немного полностью случайного, а также `newest` альбомы — ~20%.
5. Если `getSimilarSongs2` для текущего трека вернул данные — подмешивать их в пункт 3.

Жёсткие правила:
- **Никогда** не включать треки из `disliked_tracks` текущего пользователя. Дизлайк исполнителя тоже предусмотреть: если у пользователя ≥ 3 дизлайка одного исполнителя и 0 лайков — понижать его вес в 5 раз.
- Не повторять трек, игравший за последние 7 дней (кроме лайкнутых — не чаще раза в 2 дня).
- Не ставить подряд больше 2 треков одного исполнителя.
- Учитывать «пропуски»: трек, пропущенный в первые 30 с, — небольшой минус к весу исполнителя/жанра (локально).
- Детерминированность для тестов: генератор принимает `Random` с seed.

Настройки волны (чипы на экране волны, как у Яндекс Музыки): «Любимое», «Незнакомое», «Популярное у меня», а также фильтр по жанру (чипы из `getGenres`, топ-8 жанров пользователя) и по десятилетию.

Миксы на главной (как у референса Symfonium): «Микс треков» (случайные из любимого), «Микс альбомов», «Микс десятилетия» — тоже через `WaveEngine` с другими весами.

### 6.2. Дизайн-система
- Material 3, светлая и тёмная тема (по системе + ручной выбор), dynamic color (Android 12+) как опция, но по умолчанию — **цвета из обложки текущего трека** (Palette) для плеера и мини-плеера.
- Акцентный цвет приложения по умолчанию — тёплый жёлто-оранжевый (близко к духу «волны»), тёмная тема — почти чёрный фон.
- Крупная типографика заголовков секций (жирный, ~28–32sp), скругления карточек 16–24dp, обложки со скруглением 12–20dp.
- Плавные анимации: shared element обложки мини-плеер → полный плеер, анимированный градиентный фон на экране волны (Canvas + анимация, лёгкая по батарее; останавливать, когда экран не видим).
- Поддержка планшетов/складных (на референсах широкий экран): адаптивная сетка, на ширине ≥ 600dp — 2 колонки карточек и NavigationRail.

### 6.3. Навигация (нижняя панель, 4 вкладки)
1. **Главная**
2. **Коллекция**
3. **Поиск**
4. **Настройки**

Над нижней панелью — **мини-плеер** на всех экранах (обложка, название, исполнитель, сердце, play/pause, прогресс тонкой полоской; свайп вверх — полный плеер, свайп влево/вправо — след./пред. трек).

### 6.4. Экраны
**Главная**
- Hero-блок «Моя волна» (в стиле Яндекса): анимированный фон, большая кнопка play, если волна играет — название текущего трека и сердце; под ним горизонтальная лента режимов волны.
- Кнопки миксов: «Микс треков», «Микс альбомов», «Микс десятилетия».
- Секции-карусели (каждая со стрелкой «Все»): «Избранные треки», «Недавно добавленные альбомы», «Последние прослушанные альбомы» (большие карточки), «Часто слушаю», «Случайные исполнители» (круглые аватары), «Мои плейлисты».
- Pull-to-refresh.

**Коллекция**
- Сверху кнопка «Моя волна по коллекции».
- «Мне нравится» (счётчик треков) → список лайкнутых с фильтр-чипами по жанрам (как на референсе) и поиском внутри; кнопка «Волна по этому списку».
- Любимые исполнители, любимые альбомы, мои плейлисты (создать / переименовать / удалить / добавить трек), вся библиотека: Исполнители / Альбомы / Жанры / Треки с сортировками.
- Раздел «Не нравится» — список дизлайкнутых с возможностью снять дизлайк.

**Карточки**
- Альбом: обложка, градиент по цвету обложки, год, жанр, кол-во треков и длительность, play / shuffle, лайк альбома, список треков с номерами.
- Исполнитель: аватар, play «волна по исполнителю», топ-треки (из своей истории + `getTopSongs` если есть), альбомы по годам.
- Плейлист: обложка-коллаж из 4 обложек.

**Поиск**
- Поле с дебаунсом 300 мс, `search3`, результаты секциями: Треки / Альбомы / Исполнители / Плейлисты. История последних запросов (локально, по аккаунту).

**Полноэкранный плеер** (смесь Symfonium + Яндекс)
- Большая обложка (свайп по обложке — смена трека), фон — градиент из цвета обложки.
- Название, исполнитель (кликабелен → экран исполнителя), альбом (кликабелен).
- Кнопки: лайк, **дизлайк** (иконка «сердце со стрелкой вниз» или «перечёркнутое сердце», как у Яндекса), меню «⋮» (в очередь, в плейлист, к альбому, к исполнителю, информация о файле).
- Сикбар-waveform: в 1.0 — **псевдо-waveform**, сгенерированный детерминированно из id трека (стабильный узор), с плавным заполнением прогресса. Настоящая форма волны — roadmap.
- Время прошло / осталось, бейдж качества.
- Управление: повтор, назад, play/pause (крупная скруглённая кнопка в цвете акцента), вперёд, перемешивание.
- Нижний ряд: таймер сна, очередь, текст песни (синхронизированный, если есть LRC через OpenSubsonic — с автопрокруткой; иначе обычный текст), «волна по этому треку».

**Контекстное меню трека** (долгое нажатие / ⋮ в любом списке): играть следующим, в конец очереди, в плейлист, лайк, дизлайк, к альбому, к исполнителю, информация.

**Пустые состояния и ошибки**: нет сети, сервер недоступен, пустая библиотека — дружелюбные экраны с кнопкой «Повторить» и ссылкой на логи.

### 6.5. Язык
Весь интерфейс на русском (строки в `strings.xml`, без хардкода в коде). Корректные склонения через plurals («803 трека», «1 трек», «5 треков»).

## 8. Безопасность и приватность

## 9. Тестирование (выполняешь сам)

### 9.1. Тестовый пользователь
Все автотесты против реального сервера — **только под отдельной тестовой учёткой** Navidrome (например `bodro_test`), а не под учётками живых пользователей: тесты ставят лайки/дизлайки и скробблят, это засорит историю и волну реальных людей. Данные тестовой учётки читать из `local.properties`:
```
navidrome.test.url=...
navidrome.test.user=...
navidrome.test.password=...
```
Если этих данных нет — тесты против реального сервера пропускать (`assumeTrue`), а не падать, и сообщить мне в отчёте, что их нужно заполнить.

### 9.2. Unit-тесты (`./gradlew testDebugUnitTest`)
- Генерация token/salt, сборка URL, маскирование секретов в логах.
- Парсинг ответов Subsonic (успех, ошибки, пустые поля, OpenSubsonic-расширения) — на фикстурах JSON в `test/resources`.
- Репозитории через **MockWebServer**: star/unstar, setRating, scrobble, обработка ошибок и таймаутов, автовыбор LAN/WAN.
- Логика скроббла: порог 50%/4 мин, короткие треки, перемотка, пауза; офлайн-очередь — порядок, ретраи, отсутствие дублей.
- `WaveEngine`: дизлайкнутые треки **никогда** не попадают в выдачу (property-тест на 1000 генераций с разными seed), не более 2 треков исполнителя подряд, анти-повтор 7 дней, правильные доли источников с допуском.
- Взаимоисключение лайк/дизлайк, удаление трека из очереди волны при дизлайке.
- Сохранение/восстановление состояния очереди.
- Изоляция данных между аккаунтами.
- Парсер CHANGELOG.md.
- ViewModel'и ключевых экранов (Turbine).

### 9.3. Инструментальные тесты на подключённом телефоне (`./gradlew connectedDebugAndroidTest`)
- Перед запуском: `adb devices` — убедиться, что устройство подключено и авторизовано; если нет — остановиться и сообщить.
- Compose UI-тесты: логин (с MockWebServer внутри теста), навигация по 4 вкладкам, открытие альбома, запуск трека, появление мини-плеера, открытие полного плеера, лайк/дизлайк меняют иконки, экран логов показывает записи и маскирует секреты, экран истории версий показывает текущую версию.
- Тест плеера: запуск воспроизведения, сворачивание приложения (`pressHome` через UiAutomator) → через 10 с воспроизведение продолжается (`player.isPlaying`), уведомление медиа присутствует.
- Тест восстановления: запустить трек, перемотать на 30 с, убить процесс приложения (`am force-stop` недопустим для проверки — используй пересоздание Activity/процесса через тестовый механизм), перезапустить → тот же трек и позиция ±2 с.
- Smoke-тест против реального сервера под тестовой учёткой (если заданы данные): ping, getAlbumList2, stream первого трека 5 с, star → unstar, setRating 1 → 0, scrobble submission=false.

### 9.4. Визуальная проверка
После сборки установи debug-APK на телефон (`./gradlew installDebug`), сделай скриншоты ключевых экранов (`adb exec-out screencap -p > docs/screenshots/<экран>.png`): главная, волна, коллекция, мне нравится, альбом, плеер, поиск, настройки, история версий, логи. Сравни с референсами и поправь явные расхождения стиля. Скриншоты приложи в отчёт.

### 9.5. Качество кода
- `./gradlew lint` и `ktlint`/`detekt` без ошибок.
